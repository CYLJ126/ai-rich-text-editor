## HTTP 热连接

模型 HTTP 原本已有连接池，但协议适配器在 `[DONE]` 时 `takeUntil` 提前取消 HTTP 正文，正常成功流也可能无法回池。 新增真实
TCP 端口断言先复现了该问题，再改为收到 DONE 后消费正常 HTTP 尾部，完成后才发布结束标记；异常长尾默认最多排空 100 ms，配置范围
1 ms–1 s。正文增量不等待排空，调用取消和总期限仍立即生效。DONE 之前的断流仍按失败处理。

启动时预热独立 Netty 事件循环及 TLS 资源，并显式启用 HTTP keep-alive 和 TCP keepalive；此预热不访问供应商、不读取凭据，
也不意味着预先建立远程 TLS 连接。凭据仍在实际发送时读取，连接版本、执行主体、解析地址、预算、lease/fencing 和发送前校验保留。
新增不含正文或凭据的 `AI_HTTP_CONNECTION ... reused=...` 日志。

真实样本 `34591134-33b6-46c2-968d-a7cec91e9319` 已记录 **`reused=true`**。该样本 Gateway 订阅至请求发送约 31 ms， 新 TCP
空历史样本约 96 ms；样本和历史不同，不能据此推导总体分位数。原连接池的空闲及生命周期边界仍有效，长时间空闲后的请求可能重新建连。

## SSE 与浏览器绘制

- `prepareWatch` 合并建连前的权限、归属和游标检查；同一次 HTTP 准备结果只允许一次订阅，并仅允许在一秒内交接。
  延迟订阅重新检查，定时撤权检查仍从原校验时刻计时，持久事件的当前权限检查保留。
- MVC SSE 写线程由队列 256 改为直接交接：4 个核心线程、最多 16 个线程。慢写可扩容至上限，避免新连接排队等待首字；
  上限耗尽时明确拒绝。该上限是当前开发配置，生产并发容量仍需压测，不能据此宣称高并发已验收。
- 开发代理使用有界 HTTP keep-alive Agent。Nginx 增加上游连接缓存，并对 `/arte/ai-new/` 显式关闭响应缓冲、缓存和压缩， 使用
  HTTP/1.1、空 Connection 头和 identity 编码。上游 origin 派生脚本支持 HTTP/HTTPS 默认端口与显式端口。
- 首段可用正文立即提交 React 状态；后续增量共用一个待执行 RAF。移除 Markdown 的第二层 RAF，避免高频增量不断取消回调、推迟首字。
  终态等权威更新仍立即提交，卸载和登出清理待执行帧。
- 增加 `?aiLatency=1` 本机诊断，记录受理、SSE 请求/连接、正文接收、可用正文、DOM 提交和绘制机会；只保留最近 32 个样本，
  不记录正文、Token 或身份。两次 RAF 表示 DOM 提交后的绘制机会， **不是浏览器像素级首字时间**；截图仅验证最终文字实际显示。

官方 `nginx:1.27-alpine` 隔离容器中，模拟后端先发首段、延迟 1500 ms 再结束，两次首段为 2.13/1.22 ms， 同一个上游 TCP
端口被复用，响应无 gzip。当前用户环境运行的是开发代理，Nginx 结果属于单独验证。
复测脚本：[ai-streaming.py](../../../deploy/tests/ai-streaming.py)。

后续仍需完成的具体工作：

1. 继续压缩受理/派发的数据库与应用内部成本。前三批隔离口径仍是提交 77、派发首段前 105 次 SQL，稳定发送复核 18 次；
   本批真实空历史提交的 HTTP 统计为 78 次，多轮为 83/85 次。低 RTT 解除了跨网往返的主障碍，但没有把这些 SQL 自动降至数十次。
2. 对“供应商帧到达、解析完成、首段正文映射”增加细分计时，区分空角色帧、实际正文等待和解码/冷路径成本。
   在固定工作空间、固定上下文、相同参数下分别采集新连接和热连接样本，再检查剩余首字预算。
3. 定位开发环境内部抖动，再以生产等价实例和数据库部署进行连续采样、并发/慢客户端验证；当前结果不足以承诺一秒 SLA。
   如供应商正文等待已占满预算，需实测更低 TTFT 的服务或部署位置，不能用空 SSE 帧替代正文验收。
