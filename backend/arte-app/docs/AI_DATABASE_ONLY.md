# AI 控制配置只使用数据库来源

新 AI 运行时只支持数据库控制面，不再提供固定文件模式。应用服务通过显式端口获取授权、模型、连接、费率、预算和执行策略。

## 部署参数与控制快照

- `NewAiProperties` 只绑定 `arte.ai-new.enabled`、`data-source-bean`、`release-ref`、`persistence` 和 `limits`。
- `ControlConfiguration` 是受信数据库来源产生的操作快照，包含当前授权、精确模型定义及预算；不绑定 Spring 部署属性，不接受客户端配置。
- 数据库策略只能收紧部署上限。输入／输出限制、超时、上下文容量和快照有效期继续校验。
- 每个启用的 AI 容器必须提供且只能提供一个 `AiControlConfigurationSource`，并显式提供当前授权解析器。来源缺失、多个来源（包括设置了
  `@Primary` 的情况）均拒绝启动。
- 展示和预检可共享同次可信快照；受理、派发及发送边界仍按原规则重新准备，最终写入在原可写事务中复核当前授权和策略。

## 升级配置

1. 删除实际部署参数中的 `arte.ai-new.configuration-mode`。配置不再需要模式选择，旧键会因严格绑定而拒绝启动。
2. 删除 `arte.ai-new.grants`、`capabilities`、`bindings`、`connections`、`rates` 和 `budgets` 及其子键。它们不再是部署配置字段。
3. 删除 `ai-fixed` profile 和固定定义文件的显式导入；对应 profile、资源文件和示例已移除。仍启用 `ai-fixed` 的平台应用会明确拒绝启动。
4. 保留 AI／公共身份／持久化／工作空间等功能开关、物理数据源、发布标识、线程池、传输限制、部署执行上限和凭据环境映射。模型出口继续读取平台数据库策略。
5. 若旧身份映射引用了 `${arte.ai-new.grants[*].subject-id}`，将原有稳定 subjectId 原样写入身份映射，不能生成新主体替代。
6. 已在数据库中的目录、空间选择、实际模型、会话和账本继续使用原记录。文件中尚未入库的定义需要管理员通过现有配置管理入口重新配置；启动不自动导入文件或创建预算账户。

本次代码调整不执行数据库迁移、修改业务数据库或调用供应商。

## 历史记录及旧写入口

历史发布和授权数据中的 FIXED 来源编码仍保留，避免改变已有持久化编码及内容证据；它不再是可选择的运行配置来源。
旧模型定义认领发布和固定目录 ACL 范围迁移写入口明确拒绝，实际模型继续通过审核方案、连接验证和正式发布流程产生。历史查询及现有授权完整性检查仍保留。

`TextContextService` 只保留显式注入执行策略提供者的构造器，部署参数依赖缩小为 `Limits`。旧六参数构造器和
`policyProvider(...)` 覆盖方法已删除。
