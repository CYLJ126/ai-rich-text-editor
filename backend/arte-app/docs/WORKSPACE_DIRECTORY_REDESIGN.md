## 时间语义

1. 创建时间在资源创建时取一次观测值，创建后不可变。它不表示事务提交顺序，也不要求晚于父资源时间。
2. 租户／空间更新时间，在原治理事务持锁取得当前资源后，取 `max(observedNow, previous.updatedAt)`。 允许相等；版本号仍递增。不同实例无需
   JVM 内共享时钟；数据库 CAS 同时拒绝更新时间倒退。
3. 命令受理时间记录首次执行的观测时间；完成时间取 `max(observedNow, acceptedAt)`，不允许回拨导致
   已完成业务因回执构造失败而整体回滚。幂等重放保留历史受理／完成时间。
4. 同次副作用追加的事件和审计共用一个实际观测时间，不因元数据的非递减要求伪造墙钟观测值。 事件
   ID、版本和授权代次承担去重／状态判断，不按事件时间决定最新状态。
5. 系统不承诺跨资源或跨实例的时间单调性。授权期限不使用上述元数据钳制逻辑；运行耗时使用单进程单调计时。

`PlatformTimes` 集中实现观测和非递减规则。第一批保持原有 Instant 纳秒精度，避免只有写入侧或只有数据库侧
先截断，使历史创建键、回执或外部身份比较不一致。

目标微秒契约：进入持久化业务领域模型前统一截断到微秒，应用使用 Instant，数据库 DATETIME (6) 明确按 UTC 映射；
SQL、JSON、游标和领域对象中的同一业务值须保持相等。非微秒新值在边界规范化，存储侧校验；不得依赖数据库隐式舍入。 部署切换时协调
DDL、历史元数据、成员创建键、联合外键、游标格式和回执兼容，旧游标失效后从首批重查。
历史回执／审计不批量重写来冒充新的观测值。该目标放弃原始纳秒位的保真，真实需要原始精度的字段单独保存。

## 目录排序与完整性

- 唯一排序为 `(createdAt DESC, tenantId ASC, workspaceId ASC)`。时间可重复；完整 scope 打破并列。
- 所有层必须使用相同精度和 ID 比较规则。当前平台生成 ASCII UUID；若扩展为任意 Unicode 标识，须先验证 SQL 排序与 Java
  比较一致，不能假设 utf8mb4_bin 与 UTF-16 String.compareTo 对所有字符相同。
- 创建键和 scope 不可修改，游标包含完整边界值，不依赖边界行仍存在；修改名称和删除已扫描关系不导致持续存在的候选漏扫。
- 这是动态目录，不是固定快照。边界之前的新候选可能直到刷新才出现；撤权按每批新读的事实过滤，列表不是最终访问许可。
- 成员记录保留空间创建键副本，并由联合外键确保一致；不将成员加入时间误用为空间排序键。
- 事实批量读取、同批鉴权／展示复用、数据库当前读、门控、版本、成员 generation、幂等和 Outbox 原子性继续保留。

## 内部扫描契约（第二批已实现）

存储 SPI 接收受信主体和强类型边界 WorkspaceCandidateKey，返回最多 limit 个轻量键及 exhausted。 候选 SQL 只读取成员表的范围和不可变创建键，不
JOIN 空间表；展示字段由同批授权事实生成。 内部直接传递完整边界，不保存 Redis token。旧页码／精确计数也使用强类型扫描，只保留前一个键检查严格进度。
对外 token 的编码、有效期和主体绑定属于 app 导航适配。

## 公开浏览契约（第二批已实现）

`/arte/workspace/browseAccessibleWorkspaces` 返回 ResultContext 包装的 records、nextCursor、exhausted，无 total。
`/arte/workspace/countAccessibleWorkspaces` 独立返回可见数量，仍为显式全量扫描，不承诺固定时点快照。
旧页码接口保留兼容；前端选择器和服务客户端已移除页码／total 路径。

- size 为 1～100，默认 20。search 输入最长 100 字符，在已授权的当前名称上进行 Locale.ROOT 大小写规范化匹配； Unicode
  大小写扩展后的搜索值由 token 容纳。搜索改变从首批开始，不能复用不同上下文的游标。
- 默认批上限 100，最多处理 200 个候选、启动 4 批。首批取 min (size*2,batchSize)，后续扩大批次，兼顾稠密首屏
  数据量和稀疏资格的数据库往返。每批额外预取一项判断尾部，未消费的可见项不越过边界。
- 工作时间默认 1s，System.nanoTime 在批次间限制后续批次启动，至少执行一批以产生进度；不取消已执行 SQL， 不包含调度排队，也不是整个
  HTTP 的硬超时。SQL 沿用语句超时。
- 配置位于 arte.platform.workspace.directory：batch-size、max-candidates、max-batches、max-work-time；非法值启动即拒绝。
- token 为不透明 UUID，Redis cursor:v2: 状态保存主体、规范化搜索、页大小、格式版本及完整边界，TTL 沿用 cursor-ttl。
  每次续扫重新读取权限，token 不保存允许决定。缺失／过期／旧格式为 410／PLATFORM_CURSOR_EXPIRED； 主体、搜索、页大小不匹配或畸形
  token 为 400；Redis 不可用为 503，不能伪装成空目录。
- 预算耗尽可返回不足一页或空 records 和 nextCursor。exhausted 表示已观察到当前候选尾部，不保证之后没有新增； nextCursor
  只表示可继续扫描，不承诺下一页有可见项。
- 边界只越过已处理且已返回或已过滤的记录。整批鉴权后提前满页，不使用整批末尾作边界，不缓存未返回记录的权限。
  边界行删除、改名和前序关系移除不影响后续扫描；新增或名称变化在边界之前的匹配项可能直到刷新才出现。
- 精确计数不用候选 COUNT 替代可见数量；复杂权限仍逐批计算，不能以独立接口冒充低成本计数。 固定时点导出另设计快照任务，不通过长
  HTTP 事务实现。
- 选择器显示继续加载／继续查找；搜索和刷新重置游标，过期提供重新加载。首次加载仍校验当前／启动／默认空间，
  续页不重复读取偏好或重新选择空间；AbortController 丢弃迟到响应，追加页面检查重复 scope。

## 基线与后续决策

使用 `WorkspaceDirectoryBaselineTest` 与 Maven `workspace-baseline` profile，在独立临时 MySQL／Redis 中运行真实
Mapper、现有服务、连接池和有界调度器。此 profile 编译公共 persistence/workspace 测试与夹具，不改变普通构建的测试范围。
记录规模／可见比例／并发矩阵、SQL
往返与执行时间、候选批次数及拉取行数、Redis 读写、连接获取、调度排队、 延迟和每工作线程分配字节；同时保存执行计划和索引页数。原始分配字节不是存活堆内存，SQL
阶段包含驱动／数据库等待， 各指标有重叠，不能相加分摊延迟。
