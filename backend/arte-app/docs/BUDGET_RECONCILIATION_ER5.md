## 装配与权限

宿主须启用现有 AI、公共身份、公共持久化及工作空间能力；账本与公共授权必须使用同一个 `appDataSource`
，以便最终授权检查、核对和审计原子提交。没有新增开关或表。管理接口在缺少账户授权宿主时拒绝执行，不回退为模拟账户 owner。

权限分为三个独立条件：

| 条件                                        | 作用                                                   | 如何取得                                                               |
|---------------------------------------------|--------------------------------------------------------|------------------------------------------------------------------------|
| 当前有效身份、租户／空间资格及 `ai:read`    | 进入当前 scope，读取获授权财务记录                     | 现有身份、成员和 RBAC 管理                                             |
| 具体账户 `budget-account:assign-reconciler` | 查看该账户授权并指定／接替／撤销核对人                 | 对该账户的明确治理授权                                                 |
| 具体账户 `budget-account:reconcile`         | 读取该账户必要财务数据；提交还需独立 `ai:budget:admin` | 上述治理人通过公共授权命令具名指派；独立操作另由现有 RBAC 管理明确授予 |

空间管理员角色、预算 owner、模型创建者均不自动获得这些账户动作。指派不会补授成员资格、`ai:read` 或 `ai:budget:admin`
。因此治理人应先确认被指派者当前资格和独立操作，再指派主责任人。角色可以承载独立 RBAC 操作，但具体账户责任只能授予具名
SUBJECT。

## 部署准备

1. 使用现有预算准备入口初始化目标账户。显式准备会登记一个空 EXPLICIT 公共授权根；普通预算读取不创建根或授权。已有账户可再次显式准备，仍不修改费用或自动补授责任。
2. 已有数据库按既有数据库变更流程执行 [独立操作定义 DML](../scripts/arte-ai-budget-reconciliation-rbac-dml-mysql.sql)
   。全新数据库的 `arte-rbac-dml-mysql.sql` 已包含同一段。该 DML 只登记 `menu_code=ai`、`operation_code=budget:admin`
   ，完整操作码为 `ai:budget:admin`，保留已有停用状态；不授予任何用户或角色。
3. 用现有 RBAC 管理明确授予所需人员独立操作。部署账户与实际核对人不同；初始治理人可只具备账户指派权。
4. 对没有初始治理授权的具体账户，使用下述生成器准备待审阅 SQL。只在核对账户、成员代次、实际签发人和操作编号后，由可信部署身份按数据库变更流程应用并留档。
   **本轮仅验证生成内容，未对真实 MySQL 执行。**

```bash
python3 -B backend/arte-app/scripts/arte-budget-reconciliation-bootstrap.py \
  --tenant '<实际租户>' --workspace '<实际空间>' \
  --budget-ref '<实际账户>' --owner '<账本真实 owner subjectId>' \
  --governor '<初始治理人 subjectId>' --issued-by '<实际签发人 subjectId>' \
  --membership-generation '<治理人当前成员代次整数>' \
  --operation-id '<本次经审阅的唯一操作编号>' > /private/tmp/er5-account-governor.sql
```

生成器仅输出 SQL。应用者需要此目标数据库的变更权限及临时存储过程权限，不使用 `mysql --force`
；失败时回滚并检查原因。生成内容会校验当前治理人身份／成员和实际账户归属，锁定现有公共门闩，最多增加一个具体账户
`assign-reconciler` 授权、推进 ACL／授权 epoch 并记录真实签发人审计。同操作源重放不恢复已撤销授权。subject
门闩须已由现有公共身份入口初始化；不得凭猜测填写成员代次。脚本不修改余额、预留、限额、费率或角色，也不授予核对动作。

## 责任指派与核对

账户使用者在聊天费用区查看本人 `accountRef`、责任状态和挂起费用。未指定有效责任人时，界面显示“未指定核对责任人”，交由具备该账户指派权的治理人员处理。

治理人员在“账户费用管理核对”中输入本人提供的具体账户标识，显式打开账户，再读取“账户责任指派权限”。取得该账户当前授权事实后，输入稳定
subjectId 并指派。接替会同事务撤销旧有效核对授权，历史授予／撤销及公共命令回执保留；撤销也要求当前账户指派权和版本。

责任人用自己的真实身份打开同一账户。财务读取须有当前账户核对权；提交还须独立费用操作。管理页只返回调用／预留安全编号、金额、时间、状态和证据等最小财务信息，不查询目标用户聊天历史、模型输出或凭据。责任信息和公开回执不公开登录名／联系方式；无获授权显示名时用稳定
subjectId。

实际金额、币种、可归属于本次调用的账单证据、说明和远端执行结束确认均必填。聚合余额、日消费或服务恢复不能替代单次证据。证据暂缺时保留挂起资金并跟进供应商，不自动填零、释放或转移费用。

确认响应丢失后，保留原目标、请求、版本与键，先读原回执或显式确认原操作；不要重新填写另一笔操作。本人和管理入口共用调用的原核对键，接替人员也不能覆盖最终结算。浏览器不会自动重放核对或责任指派写请求。

撤销身份、空间资格、账户授权或独立操作后，后续读取／提交按当前事实拒绝；最后的结算事务还会重新检查。权限不足不能通过账户标识或浏览器旧回执绕过。独立全局操作不足不影响合法只读，但该责任人不会被展示为已有完整处理资格。
