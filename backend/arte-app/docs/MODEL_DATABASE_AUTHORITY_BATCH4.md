# 数据库模型管理第四批：租户模型、跨空间使用和凭据用途

> 后继设计（2026-11-03）：[模型配置重构 M0](../../../ARTE%20AI%20模型配置需求及设计.md) 已定稿，M1～M5 尚未编码。本文保留当批实现与验证事实；后续
> DATABASE 新建模型采用审核方案／实际资源分离及独立空间预算契约，不按旧目录直供或分散创建流程实施新批次。

日期：2026-11-01。

## 交付范围

新增 `/AI/ModelSharing`“租户模型与授权”，模型管理页提供入口。页面使用已认证的公共空间目录选择管理空间和授权空间， 复用公共模型
ACL、成员代次、治理事务、CAS、幂等回执、审计、Outbox，以及第三批的审核模型与费率。

本批支持租户私有模型创建、草稿／验证／发布、指定同租户空间使用、主体与角色／空间动作授权、撤销和模式共享，
并增加与模型动作独立的租户凭据用途审批。空间模型保持原归属和主空间使用；需要跨空间使用时创建租户模型，
不迁移旧模型归属、不复制个人密钥、不修改旧目录切换清单。旧目录迁移仍为第五批。 租户模型只通过已验证草稿及租户凭据发布，旧
associateModelResourceVersion 采用流程继续限定空间模型，防止借旧目录资格绕开新门控。

## 归属、管理和执行

模型增加固定 `managementScope`。WORKSPACE 资源的管理空间也是归属空间；TENANT 资源的真实归属没有 workspaceId，
管理空间只用于配置草稿、凭据维护和发布操作。新 HTTP 模型视图增加 `ownershipType`，原 `scope` 继续表示管理空间。

现有模型表的物理 `workspace_id` 保留 NOT NULL 和原外键，语义明确为固定管理空间；不以它推断租户模型的使用范围。 旧空间模型
JSON 缺少 managementScope 时按原归属空间恢复；原稳定资源 ID、创建者、绑定族、历史发布及账本不变。
模型展示名称可在发布已验证草稿时更新，不把名称当作不可变身份。

租户模型的允许使用空间独立保存，创建时仅包含明确选择的管理空间。范围可以清空，表示全部禁止。
添加其他空间要求操作者能读取该同租户空间；租户角色不替代空间资格，也不自动授予任何模型动作。

实际调用仍属于目标 tenantId／workspaceId／subjectId，使用目标主体自己的兼容预算和账本。 运行出口检查当前租户政策与实际执行空间政策，管理空间不代替目标空间准入。
管理空间中的编辑、验证、发布仍要求其当前空间资格和对应模型动作；本批不提供管理空间迁移或凭据责任转交。

## 创建与配置

1. 确认已有数据库审核连接和第三批模型／费率方案，两级政策允许对应连接及用户提供的凭据。
2. 在“租户模型与授权”选择管理空间，填写名称并创建租户私有模型。
3. 创建同时要求当前空间 model:create、租户治理资格，以及当前 RBAC 的 tenantModel:create、aiConfiguration:manage 或 admin
   之一。 后者只是额外创建资格，不能绕过租户治理和空间创建检查。租户 OWNER／ADMIN 不自动获得模型 ACL。
4. 打开“模型草稿与发布”，选择新租户模型，保存配置和明确的租户密钥，验证当前连接并发布固定版本。
5. 返回授权页，保存允许使用的空间；在“授权所在空间”选择实际目标空间，再授予成员 model:read／model:use 等需要的动作。
6. 由租户凭据责任主体单独审批“允许使用租户凭据的成员”。具备 ACL 管理资格不代表可以替责任主体审批密钥用途。
7. 目标成员进入目标空间，按原流程准备空间 AI 和本人兼容预算，重新加载聊天配置并应用租户模型。

创建或发布不会准备 AI、授予预算、提高额度或重置余额。没有兼容预算继续报告 NO_COMPATIBLE_BUDGET。 审核方案、个人发布和历史费率均保留固定版本，不引入
latest 执行解析。

当前两级 personalCredentialsAllowed 继续作为用户提供密钥的保守来源上限，也约束租户凭据； 它不表示团队用途已获批准。供应商、协议、目的地主机和部署
origin 硬上限继续检查。

## 动作授权和共享

页面直接使用既有 /arte/resource/access 接口，显示当前 aclVersion 和分页授权列表。

- 指定成员：保存独立 SUBJECT 授权，可选 ISO 到期时间。租户模型按当前租户成员代次绑定，不依赖其在管理空间的成员资格。
- 空间角色／整个空间：使用明确 SPACE_SHARED 规则，作用于页面选中的授权空间。保存会替换由模式维护的共享规则，页面要求确认；
  独立主体授权保留。关闭模式共享不撤销独立主体授权。
- 撤销：携带当前 ACL 版本及指定 grant 的版本，只撤销该来源；其他有效允许来源仍可能保留。

资源授权不提供租户凭据。范围准入不授予模型动作。租户模型的资源 ACL 可以跨其准入空间使用， 实际调用仍需当前有效的目标空间成员资格及
workspace:ai:use。 没有管理空间读取资格的使用者可在获准目标空间发现和调用模型，不能据此修改管理空间的草稿或密钥。

租户成员选择器要求租户成员治理资格，有界分页，公开主体 ID、角色和状态，不返回内部成员代次。 没有成员目录资格时，仍可填写已知稳定主体
ID；服务端重新核验目标成员，不能用用户名或自报成员代次授权。

## 个人与租户凭据

Credential 增加 PERSONAL／TENANT 类型。旧记录和旧回执缺少该字段时保持 PERSONAL。
空间模型只接受个人凭据，租户模型只接受明确的租户凭据；不能通过更改请求类型把个人密钥转换成共享密钥。

两类密钥均采用原 SM4-GCM 密钥环。租户凭据的认证附加数据增加独立用途标记；旧个人密文的认证数据保持兼容。
密钥不出现在模型／授权视图、命令回执、浏览器本地或会话存储；验证和实际调用只在服务端短暂解密。

维护责任始终由服务器记录的责任主体持有。只有责任主体且当前有 model:edit 时，才能替换密钥或修改租户用途名单。 模型
edit／validate／publish 权限不允许读取明文，也不自动允许维护或消费别人的凭据。

用途审批固定当前 credentialVersion，并绑定每位消费者当时的租户成员代次。 退出租户再加入不会恢复旧批准；重新授予模型 ACL
后也仍需新的凭据用途审批。 轮换或撤销后旧发布与旧用途记录均不能发起新调用；须重新验证、发布，并明确审批新代次。
页面对旧代次名单显示警告，可由责任主体确认“以当前代次重新审批名单”，不会自动升级。

个人凭据保持本人用途限制，模型分享不会改变它。租户凭据也只供同一租户模型、明确空间和获批消费者使用， 不构成全租户通用
SecretRef 或跨模型密钥池。

## HTTP、事务和恢复

新增 POST 前缀 /arte/ai-new/model-sharing，沿用认证会话、严格请求字段、ResultContext、平台错误及服务端追踪标识：

| 端点                           | 请求                                                                       | data                                     |
|--------------------------------|----------------------------------------------------------------------------|------------------------------------------|
| createTenantModel              | scope、name                                                                | 模型资源命令回执                         |
| getModelSharing                | scope、resourceId                                                          | policy、脱敏 credential、mayManageScopes |
| updateModelUseScopes           | scope、resourceId、expectedVersion、workspaceIds 完整集合                  | 策略命令回执                             |
| updateModelCredentialConsumers | scope、resourceId、expectedVersion、credentialVersion、subjectIds 完整集合 | 策略命令回执                             |
| listTenantModelMembers         | scope、current 可选                                                        | PageResult，size=100                     |

写入必须带原样保留的 Idempotency-Key。策略视图只公开 resourceId、管理 scope、空间 ID、消费者 ID、凭据业务版本和策略 CAS 版本，
不公开内部成员代次、密文或发布快照。凭据响应增加 kind，模型草稿的 replaceModelCredential 请求增加可选 credentialKind，旧请求默认
PERSONAL。

模型身份与初始私有 ACL、策略和范围索引在创建原事务内保存。 策略更新按原主体、父租户和空间门控顺序取锁，当前读核验资格后 CAS
保存；租户 epoch、回执、审计与 Outbox 一起提交。 消费者的主体门控在父租户锁之前按序取得。失败整体回滚，不通过另开事务伪造最后授权。

浏览器按账号和完整管理空间保存严格白名单请求及原键，支持刷新后确认，不自动重发。 凭据明文继续只走原内存输入流程。存储失败或记录损坏阻止新操作。
网络或无法确认的成功响应保留原操作；版本冲突保留草稿，显式重读后再保存。 已经确认保存、仅后续读取失败时只重读，不重复写入。范围编辑资格与凭据责任分开显示，ACL
读取拒绝不推断凭据责任。

## 发现、受理、派发和外发

运行候选来自原不可变发布证据及明确范围索引，所有个人／租户发布仍使用受保护命名空间。 拒绝、缺失证据或缺失范围不能回退旧
Grant 放行。

展示及当前执行分别重新核验模型状态和精确内容、公共 ACL、范围、当前成员、目标空间政策、凭据代次及用途。 受理和派发 Permit
在实际原写事务重查，不把先前许可当作永久授权。 真正外发前再次校验真实 RUNNING Invocation、目标
ExecutionOwner、固定发布、当前用途和兼容预算，随后才解密。

租户策略及索引当前阶段有明确上限：每租户 256 个租户模型策略，每策略最多 256 个使用空间及消费者； 运行合并仍受原 256
项定义／发布限制。读取有界核验租户策略与完整范围索引，不把损坏、丢失索引或权威故障伪装成空目录。 两张新表及模型表通过组合唯一索引／外键绑定同一租户。

撤权在最后门控前提交会阻止后续写入或发送；已经发出的供应商请求不能追溯撤回，继续按原发送事实、UNKNOWN 和结算规则处理。

## 部署顺序

1. 备份并核对已有公共平台、ACL、模型资源、草稿／凭据及个人发布表。
2. 显式执行一次 [arte-ai-model-sharing-ddl-mysql.sql](../scripts/arte-ai-model-sharing-ddl-mysql.sql)： 为原模型资源增加组合唯一索引，新建
   arte_ai_model_sharing、arte_ai_model_use_scope。 脚本不回填旧模型、不更改原归属、不转交任何密钥用途；应用启动不执行 DDL。
3. 升级全部 API／Worker 节点并排空旧二进制，再显式配置：

```properties
arte.ai-new.configuration-mode=DATABASE
arte.ai-new-model-management.enabled=true
arte.ai-new-model-publication.enabled=true
arte.ai-new-model-sharing.enabled=true
```

本地可将共享开关写入 backend/profile/app.properties，重新构建后由原过滤资源导入； 也可在 IDEA Run Configuration 使用
ARTE_AI_NEW_MODEL_SHARING_ENABLED=true。原加密主密钥配置不变。

默认共享开关为 false；关闭时旧空间／个人模型不读取新表。显式开启但缺表拒绝启动。 已有租户模型策略时关闭共享门控同样拒绝启动，不能静默恢复旧资格来源。
旧个人发布的启动安全检查继续要求完整 PUBLIC ACL 和个人／租户凭据解析器。

管理空间仍为固定维护入口；本批不迁移它，不提供凭据责任转交、租户成员治理 UI 或跨租户模型使用。 这些边界不影响本批明确的同租户目标空间执行。
