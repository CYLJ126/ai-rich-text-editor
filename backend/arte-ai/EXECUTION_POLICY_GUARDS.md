# AI 执行政策与受理门控：第 3 批

日期：2026-10-30。对应顶层设计详细设计第 4、5.2～5.3 节，在发布目录／预算定义及模型使用资格端口基础上，拆出执行政策，并把当前资格复核接入实际受理、派发写事务和模型发送前边界。保留
FIXED／DATABASE、HTTP、执行记录及账本格式。

## 政策契约与来源

`spi.control.AiExecutionPolicyProvider` 提供异步 `current(context)` 及原同库写事务内同步
`inCurrentTransaction(context)`。
`pojo.control.AiExecutionPolicy` 包含最大输入字节、输出 Token、输出字节、执行超时和输入快照保留时长；有效值逐项与部署上限取较小值，客户端及自定义来源均不能提高部署上限。

默认 `ConfigurationExecutionPolicyProvider` 经 `ControlConfigurationReader` 读取现有来源的 `limits`，FIXED
使用现有配置，DATABASE 使用已核验来源返回的限制，再与部署配置相交。本批没有增加租户／空间数值政策字段、数据库表或管理 API；现有
DATABASE 来源仍沿用部署数值限制。后续数据库收紧值由受信提供者在两个方法中一致读取、按当前范围验证，并与平台限制相交，无需修改上述业务调用方。

公共成员、空间启用状态及现有公共政策继续由 DATABASE 来源及公共门控校验；不据此宣称公共模型
ACL、provider／protocol／destination 政策白名单、凭据用途治理或全部动态配置迁移已经完成。网络出口、连接池和 SecretRef
环境解析仍保留既有实现。

模型发现、文本上下文组装、普通受理、派发、Tool Chat 根计划及后续模型输入均使用政策提供者。`ExecutionPolicyChecks`
集中复核原请求、固定绑定、输入快照／工具集合、大小、输出限制、期限和快照保留约束；收紧限制时拒绝超限的原计划，不改写原执行身份、输入、固定引用、期限或费用记录。

## 实际执行边界

`spi.auth.AiAdmissionAuthorizationGuard` 接收 `Check`，包含原请求、精确绑定、可信输入快照、可选
ToolSet、边界类型及明确预算引用。普通调用预算沿用原上下文；Tool Chat 根上下文仍不带单一预算，门控从固定预算计划单独取得模型预算，不能借此更换根执行身份或预算归属。

默认 `ConfigurationAiAdmissionAuthorizationGuard` 先完成异步预检，组合模型资格、预算定义、当前政策及发布依赖。返回的内存
`Permit` 绑定原请求；它不是持久化授权或可重放的发送令牌。

| 边界                               | 当前复核与落点                                                                                                                                                                                                                                                               |
|------------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| 普通聊天／重新生成／模型子调用受理 | `AdmissionInvocationCoordinator` 调用带同步回调的 `ExecutionStore.accept`；`MybatisExecutionPersistence` 在写事务内先执行门控，再处理 Invocation／Turn／Outbox。撤权或政策收紧时这些业务写入整体回滚；已组装的输入快照可能已独立保存，不代表已受理。                         |
| 原子模型派发                       | `GenerationDispatcher` 将许可回调传给 `DispatchPreparationStore.prepareDispatch`；原事务先复核，再创建 Attempt、取得费用预留及标记派发。拒绝时不创建 Attempt／预留。                                                                                                         |
| 分步派发兼容路径                   | 当前许可也进入 `ExecutionStore.markDispatch` 的原写事务，在发送标记前复核；已独立创建的未发送 Attempt／预留仍沿既有恢复及结算链路处理。                                                                                                                                      |
| Tool Chat 根 Run 与推进            | 创建／重放、编排推进同时组合模型门控和既有 `ToolChatAccess` 回调；根 Run 固定计划与预算选择均复核，模型子调用再经过普通受理和模型派发门控。工具本身继续走已有 ToolAdmission／ToolDispatcher 授权及计费流程。                                                                 |
| 真实模型 HTTP 发送                 | `DefaultModelGateway` 在订阅上下文传递 GatewayCall 和可选 ToolSet；`HttpConnectionRuntime` 的发送过滤器经 `ConnectionManager.resolveCurrent(ref, call)` 调用同一门控，复核当前资格／预算／政策及精确绑定、连接。之后才解析凭据并执行 HTTP exchange，不持数据库事务等待网络。 |

发送过滤器中的政策拒绝明确转为“已知未发送”的失败；不会仅因该拒绝把费用归为未知。实际请求已经可能发送后的失败仍保留原
Attempt／fencing／UNKNOWN 和证据结算规则，不能凭撤权释放未知预留。派发结果的供应商核对改用本次门控解析的连接，避免 DATABASE
执行又回读文件连接。

普通根调用可复用入口的可信异步准备，最终写入仍以事务当前读为准；模型子调用单独准备自身上下文。并发同意图 Tool Chat
受理遇到已胜出的另一固定计划时，回到既有重放链路，为获胜计划重新准备许可，不将候选许可用于另一个 Run。

## 原事务当前读

`AiControlConfigurationSource.configurationInCurrentTransaction` 是迁移桥的同步契约。DATABASE
实现验证原物理数据源的可写事务，加入该事务，在公共身份／租户／空间／成员／政策门控下读取当前 AI 配置和预算定义。公共父范围门控先于
AI Invocation／Run／账本等领域锁。

FIXED 原事务复核当前固定授权；app 的 RBAC 适配同时以稳定 subjectId
核验当前有效账号。模型、预算及政策端口都增加同步事务方法；只实现异步查询的自定义提供者不能直接参与写入，默认拒绝。自定义实现必须同步、同库、检查当前状态，不能调用
Reactor `block()`、另开事务或等待网络来替代原事务门控。

`ControlConfigurationReader` 的同步当前读不读取 Reactor 的展示／准备快照。只在一次同步回调内，按完整
ExecutionContext、来源身份和实际事务标记共享当前配置；跨上下文、来源或挂起后另启事务均拒绝。回调完成或异常时清除线程内共享状态，不跨命令缓存允许结论，也不将异步只读结果提升为写入许可。

带授权回调的新存储重载默认拒绝不支持的实现，禁止静默退回无门控方法。旧无回调方法保留给既有内部存储调用及工具流程；生产模型链路使用新重载。Spring
按 SPI 注入政策和门控，两个端口均支持替换；`FixedControlCatalog` 和旧构造器继续作为兼容入口。

## 验证与范围

专项验证覆盖：预检后收紧政策导致受理回滚、派发拒绝且无
Attempt／预留；原物理事务／只读事务／无事务及不同请求隔离；全部数值政策收紧；发现使用有效限制且不能扩大部署上限；异步政策不能代替写事务实现；旧读取范围不覆盖当前读；同步回调共享及异常清理；挂起事务隔离。HTTP
测试在实际 exchange 边界收紧政策，验证零凭据读取、零请求且失败为已知未发送。DATABASE 集成覆盖成员撤销、替换政策 SPI
后发现及真正受理都生效。
