# S4-06：ChatNew 工具聊天与显式再生成

日期：2026-10-21。基于 S4-05 的耐久 Run 实现前端闭环，入口仍为 `/AI/ChatNew`。没有修改业务配置、执行 SQL 或连接实际供应商。

## 1. 页面与恢复

- 输入区“工具设置”按需查询此环境是否开放工具聊天，再分页读取当前账号／空间的工具绑定。默认关闭；仅选择已有绑定，不自动创建配置或授予资格。
- 用户明确选择工具、与模型账户相同币种的 Run 总费用上限；模型／账户沿用已应用设置。高级区域可收紧模型轮数、工具数和只读并发。总期限沿用模型设置，人工等待占用原期限。
- 普通文本继续走 `turnsForChat`；工具聊天走 `submitToolChat`。受理前将完整请求、幂等键和只读意图保存到当前标签的账号／租户／空间／会话键中。网络、408、5xx
  和幂等内容冲突保留原请求，人工“继续确认”不换键、不改输入。202 只表示受理。
- 有 Run ID 后，刷新只读取原 Run；未受理的恢复记录不会自动提交。工具集合是当前会话本次编辑选择，刷新默认关闭；已受理 Run
  或未确认请求使用其原固定集合。
- Turn 候选按 `INVOCATION`／`TOOL_CHAT_RUN` 分流。Run 的最终模型子 ID 不作为普通 Turn 候选查询或重新生成。搜索使用命中的类型化根引用读取
  Run 完整回答，并核验真实 finalInvocationId 和 messageId。
- 保留现有目录窗口、布局与消息滚动锚点。工具过程内容变化通知原有跟随逻辑，浏览旧消息时不会强制滚到底部。新增 CSS 只限定工具人工控制
  JSON 的换行与局部滚动。

Run 卡片展示当前阶段、模型／工具步骤数、独立事件摘要、最终回答、按币种
L／C／H／available，以及审批和核对入口。步骤数是服务端固定计划数，不是成功调用计数。参数与决定窗口由原有审批查询展示；根检查点中的真实子
ID 用于人工控制，不用 Run ID 冒充 Invocation。

停止先保存原命令，再调用 `cancelRun`。同版本也合并 `cancellationRequested`，不会被较旧的同版本 false
清除；耐久请求不等于业务已停止／回滚。UNKNOWN 不提供普通重试入口，允许查询原核对记录与请求停止等待。

## 2. 观察与性能边界

Run 没有公开 SSE：活动根使用 1.5 秒串行轮询，不重叠；只有根版本对应的事件尚未补齐时补读独立事件游标，单批最多 100、页面保留最近
100。预算在根推进时或每 10 秒读取，版本独立合并；同币种金额始终是字符串，不求浮点和或用账户差推算。

`WAITING_MODEL` 只订阅检查点中实际模型子 Invocation 的文字；耐久文字和实时 offset 合并，不显示工具参数
JSON。进入工具阶段清除模型预览，完整 Run 结果优先。SSE 不可用时仍读取原模型子结果。不同模型子调用的游标不拼成 Run 游标。

失败按 2／4／8／16／30 秒退避，连续五次失败或观察满五分钟暂停，用户可继续读取原 Run；401／403／404 停止自动观察，失权清除当前回答／过程。终态仍有
held 时低频查询，不把它计为零费用。组件卸载、切换会话／空间或退出登录取消前端读取／订阅，忽略迟到响应，不发送业务取消。相同
scope、凭据和完整参数的并发 Run 读取复用既有 sharedRead，不缓存授权。

Run 受理／完成会先作废旧历史版本，再复用历史刷新队列，避免与在途历史读取竞争时发布旧会话版本。无法保存／校验恢复记录时禁止竞争提交并提示保留页面；可恢复的写入故障提供存储复查。

## 3. 三种明确动作

这些动作先准备可检查的内容，均不在点击时隐式重发原 Run；普通文本的“重新生成”仍保留原候选语义。

| 动作             | 本批实际行为                                                                                                        | 约束                                                                                                                                         |
|------------------|---------------------------------------------------------------------------------------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------|
| 只重写回答       | 用户确认后，将原问题、完整最终回答与旧回答生成时间放入新的文本草稿，关闭工具；再次发送创建新的文本 Turn／Invocation | 不重放原始工具输出；显示未核实资料观测时间和来源时效，可能过期；只重写也有模型费用                                                           |
| 重新读取最新数据 | 用户确认后，将原问题及原允许集合中的只读绑定放入新工具聊天草稿，再次发送创建新的 Turn／Run                          | 使用当前模型设置、当前资格与新预算上限；`submitReadOnlyToolChat` 在实际固定集合及幂等重放时拒绝任何非 READ_ONLY 工具，防止绑定后来改成写工具 |
| 重新执行操作     | 展示原允许集合中的写工具配置引用，前往已有工具页明确选择操作、核对参数、重新预览、提交并按当前政策审批              | 允许集合不代表实际已执行；不复制旧参数／授权／决定，不创建自动写重试。UNKNOWN 无此入口                                                       |

上述新 Turn 方案将用户确认的意图保留为真实用户消息；不伪装成旧 Turn 的候选，不自动选取历史 raw tool 消息作为输入。首期没有实现工具级
freshnessPolicy、resourceVersion／sourceDigest／maxAge，也不承诺旧资料实时有效；结构化复用原始工具输出仍需单独实现当前资源读取及外发授权。

## 4. 新增 HTTP 与验证

沿用 `POST /arte/ai-new/tool-chat/*`、ResultContext、当前登录及真实空间授权：

- `discoverToolChat`：`{scope}` → `{enabled}`，反映独立聊天和执行入口是否开放，不表示工作节点或供应商健康。
- `getRunActions`：`{scope,runId}` → `{runId,text,answeredAt,readOnlyBindingIds,writeBindingIds}`。仅本人当前可读且成功的
  Run 可准备；不返回工具配置、参数、输出或旧授权。answeredAt 是最终回答生成时间，不是工具观测时间。
- `submitReadOnlyToolChat`：输入、202 RUN 回执及 Idempotency-Key 与 S4-05 `submitToolChat` 一致；额外要求实际固定集合全部
  READ_ONLY。原写入口不改变。

部署仍按 [执行说明](TOOL_CHAT_EXECUTION.md) 的四项服务开关及 Worker 开关操作；本批不修改默认关闭状态、不增加 DDL。真实供应商、真实
RBAC／业务库、多节点与生产负载验收不由模拟浏览器或 H2 代替。

若提示“此环境尚未开放工具聊天”，在本机 `backend/profile/app.properties` 显式添加
`arte.ai-new-tool-chat.enabled=true` 和 `arte.ai-new-tool-chat.worker-enabled=true`，确认原
execution.enabled／worker-enabled 已启用，再重新构建并重启后端。profile 到运行时的五项属性映射已补齐，前序 S4
表结构须已部署；本批不自动执行 SQL。

隔离浏览器复现：在 `frontend` 运行 `node scripts/tool-chat-s406-browser/server.mjs`，打开
`http://127.0.0.1:5246/`。页面使用真实 BusinessChatPanel、工具选择、Run 观察和人工控制组件，HTTP 为可查看 `/fixture/calls`
的固定模拟服务，不具备真实业务授权或执行。测试按钮只切换模拟状态。

本轮自动化和浏览器验证结果见 [实施记录 §37](TOOL_IMPLEMENTATION.md#37-s4-06chatnew-工具聊天与显式再生成2026-10-21)。

## 5. 模型工具能力升级（2026-10-21）

ChatNew 使用配置发现新增的 `toolCallsSupported`，标记支持工具的模型。缺失或 false 时不能开启新的工具选择；已有选择仍可关闭。
工具开启后切换到纯文本模型会阻止发送并提示切换模型或关闭工具，不会自动替换模型、清空工具选择或改变原待确认请求。 服务端仍在新
Run 受理前验证模型及网关；205003 会显示明确的模型／协议不支持提示。

平台管理员可在“发布新模型”中基于已发布文本能力追加 TOOL_CALLS 能力版本及模型绑定，保留所有旧版本；原请求、幂等键与 CAS
版本在网络不确定时完整保留。 发布模型后先更新默认模板的模型批准名单，再由已有空间显式选择新模型，最后在聊天页应用。
完整操作和部署边界见 [执行说明 §6.1](TOOL_CHAT_EXECUTION.md#61-模型工具能力发布与空间启用)。个人工具配置页无需为此修改参数或重新发布工具。
