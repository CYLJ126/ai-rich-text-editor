# 会话搜索 S5 验收记录

本阶段使用本机真实 ES／IK、Redis 和随机隔离 MySQL，验证固定标注、真实扫描投影、HTTP
契约、浏览器双入口及代际回退。没有迁移现有业务库、创建正式索引、开启正式查询或调用模型。生产环境的
RBAC／灰度路由、真实历史语料质量与容量仍须在部署环境验收。

  输出生成。24 个主题覆盖空会话标题、问题、完整／部分回答、非最新且同文的两个候选、中文、大小写、编号、代码、长正文、XSS
  文本、空白／不可见与零结果；另有 40 条共同命中验证跨页。
- `SearchQualityAcceptanceTest`：从 MySQL 权威快照，经生产 Source／Store／Worker／Lifecycle 写入真实 ES；查询通过生产搜索服务、Redis
  和 MySQL 当前资格复核。所有页核对确定性集合及重复，前五按指定 entryKey 计数；逐条打开指定
  turn／message／invocation，核对真实耐久输出身份。
- `scripts/verify-conversation-search-s5.sh`：需要与 S3 相同的基础设施环境变量及 JDK 21。先验证真实 IK、规则 DSL
  与配置，再运行较长的扫描验收。未提供依赖时脚本直接失败，不以跳过基础设施测试算通过。可附 `-o` 使用 Maven 离线缓存。
- `search-acceptance/s5/`：机器结果、v1 漏召回基线、IK 词典／配置 SHA-256 与浏览器截图。每次复验原始结果写入
  `target/search-s5-report.json`。

```bash

```

## 规则修正与重建

v1 的 smart 单字段在固定集漏掉 6 条查询。真实 `_analyze` 显示：`北京地铁`、`身份证号码`、`单元测试` 的整词与短查询不一致，
`返回空值` 还有歧义切分。原查询和预期身份保留，未通过删掉难例来提高指标。

当前 v2 保留对称的 IK smart 主字段和编号辅助字段，增加 `recall`（IK max_word 索引，smart 查询，原权重的 1/2）与 `literal`
（中文逐字、其他文字按词，零间隔连续短语，原权重的 1/4）子字段。literal 只对含中文的查询启用，不做散字
OR、任意前缀或模糊扩展；全停用词先由实际查询分析器判定为 `match_none`。统一高亮合并同一原文的辅助字段偏移，并使用 ES 9 要求的
`require_field_match=true`；返回仍是安全文本及区间。

默认规则及物理前缀改为 `v2`／`conversation-search-v2`；稳定消息 entryKey 不变，extractorVersion 仍为
v1（抽取内容未变）。旧索引不能只换配置后复用：须新建 v2 物理代际并回填。显式 v1 配置保留旧映射／DSL；跨规则的现存会话返回明确过期，不能将
v1 游标送到 v2 索引。代码未创建或切换正式 alias。

新增子字段会增加索引与分析开销；本次小规模结果不能替代生产长文本容量评估。词典指纹见 `ik-dictionaries.sha256`
；更改词典／分词规则要另建代际并重新跑固定集。

## 同步链路缺陷修复

真实持续扫描暴露了两处此前短样例未覆盖的问题，均已补回归：

- 搜索进度曾通过 JDBC `Timestamp` 解释数据库本地时间，再与 JVM epoch 比较。本次 MySQL 会话／连接时区组合产生 8
  小时偏差，首轮后不再及时扫描。改为搜索专用 SQL 返回数值 Unix 毫秒，租约、退避和检查点到期统一使用数据库时钟，不改原执行存储的时间
  Mapper。新增真实调度第二轮改名用例，不调用 `due()` 或修改检查点。
- 默认发现批次 20、每 tick 处理 10 时，持续发现和校准可不断补充队列，无法到达可切换的静止检查点。现在先排空可执行批次再发现下一批，源扫描与校准共用这一预算；尚未到退避时间的失败不会阻塞新发现。新增
  batch 20／work 1 的回归，并用本次较大数据验证默认值可完成校准。扫描 tick／batch／work 默认参数未因测试而扩大。

若某环境曾用旧代码创建搜索进度，应以新规则新建物理代际及独立进度；不能将旧错误时钟形成的未来 next_at
当成新实现验证。本项目现有业务库此前未执行搜索迁移，本次无需修改业务库的旧搜索状态。

## 环境与统计口径

ES／IK 9.4.2，Java Client 9.4.5，Redis 7.4.9，MySQL 8.4.11，JDK 21.0.8，macOS arm64。查询索引两分片、零副本；这是隔离验证配置，生产默认一分片、一副本未调整。

初始源数据：566 个会话、556 个轮次、10 个持久候选，生成 1,132 条索引记录。包含 500 个背景会话与问题、40 条跨页命中、24 个主题和两个不同
owner／space 的反例。使用测试连接池（最大 8）；扫描仍是 tick 250ms、batch 20、work 10、预算 2s、租约 60s、周期校准
1h，没有修改源检查点或强制任务到期来加速。

新鲜度独立于固定质量集：一批 10 组新会话，分别提交问题、耐久回答和标题改名，记录每次返回后的单调时钟，创建新 PIT
并遍历结果，直到对应身份首次命中；每类 10 个样本。另有两个同主体查询客户端每次读取真实结果并关闭搜索，受同一主体三名额约束。探测间隔
500ms；含探测误差，不能当毫秒精确提交时刻。此阶段不手动 refresh，也不等待／修改后台检查点。N=10 时 nearest-rank P95
等于最大样本，样本数不足以证明生产 SLA。

固定质量准备允许一次 refresh；这不属于新鲜度测量。后台监控每秒记录
state／pending／failures／entries／rounds／missing／lastSuccess，原始时序保留在结果 JSON。

HTTP 测试使用生产 MVC 控制器／异常映射及真实三个依赖，身份解析器是固定测试替身，不代表生产 RBAC 已认证。两个用户／空间隔离、旧
PIT 的归档资格重检、归档后普通详情拒绝、撤权拒绝及真实候选结果身份均纳入验证；真实归档命令仍未实现。

可选浏览器验收：运行后端脚本前设置 `ARTE_SEARCH_S5_BROWSER_PORT=15145`；完成质量及新鲜度后，测试会在
`target/search-s5-browser-ready` 写入本机桥地址并等待（最长 15 分钟）。另启动：

```bash
node frontend/scripts/search-s5-browser/server.mjs
```

浏览器访问
`http://127.0.0.1:5143/`。空间发现／模型选项使用固定替身；会话目录、详情、元数据、搜索、轮次窗口、调用快照全部通过 HTTP 桥进入真实 MVC／服务／存储，不模拟搜索响应。桥只监听 loopback，白名单不含创建／改名／发送请求。完成后关闭页面，创建 `

read alias 和关闭本测试 Redis 客户端验证查询失败而 MySQL 普通详情仍可读取，未停止共享 ES／Redis。真实服务器断电、网络分区和生产熔断不在此次证据内。

`SearchSyncInfrastructureIntegrationTest` 增加真实回退演练：g01 → g02 后改变归档资格，重新 prepareActivation／完整校准 g01
后切回，g01 中归档记录为 0；g02 与其旧 PIT 代际保留。S3 继续验证同规则切换后旧 PIT 固定原代际、新搜索使用新代际。

## 部署与回退交接

1. **数据库状态**：S5 只执行随机验收库 DDL，阶段交付时业务库未迁移。用户后续已确认执行四表搜索迁移，本轮未复核业务库或执行回填；其他环境仍须先备份并按
   S2 独立迁移脚本及其部署要求执行，不能用隔离测试代表业务环境迁移成功。
2. **索引准备**：按目标环境真实 ES／IK／词典和副本配置准备全新 v2 物理索引，指定固定扫描 generation，核对 alias 与
   rules。新增受控[启动初始化](CONVERSATION_SEARCH_INITIALIZATION.md)
   ，首次部署可显式开启后自动创建；默认仍关闭。已有代际升级／回退继续显式准备与切换，保留可用旧代际，不复用物理名。
3. **回填观察**：先开主开关及扫描／回填／校准，查询保持关闭。记录全库循环时间、owner 积压、失败／缺失结果和提交→新 PIT 的各类
   P95；查询不等待全历史追平。局部数据可用与无遗漏是不同结论。
4. **有限开放**：配置是实例级开关，没有应用内 owner 白名单。使用部署环境已有的灰度实例／网关范围路由限定目标
   tenant／workspace；未配置隔离路由就不能把全局 query-enabled=true 当成按范围灰度。生产 RBAC、未授权空间和用户切换必须实测。
5. **回退**：关闭灰度实例查询并移出路由，普通聊天继续使用原存储；保留消息、预算和扫描进度。代际回退必须先按当前源／归档资格完整校准目标，通过一次性
   activation epoch 后原子切 alias。跨 v1／v2 规则需同时匹配应用规则配置，明确让旧搜索过期，不能仅切
   alias。旧索引保留至少最大搜索存续期加清理余量并核对活动会话；此阶段未删除正式索引。
6. **开放判据**：固定集匹配、身份定位、权限及游标故障处理须通过。P95 ≤30s 是候选目标，若此次或部署规模未达，按实测决定扫描配置／试运行范围；不得把最终一致或一次
   ES 成功视为新鲜度通过。正式容量、生产身份链和真实业务灰度尚未执行。
