# AI 控制面装配收口与兼容验收：第 4 批

日期：2026-10-30。承接发布目录／预算定义、模型使用资格、执行政策／受理门控前三批，收口生产装配与旧依赖。保留既有 FIXED／DATABASE
模式、HTTP、配置记录及耐久执行／账本格式，不执行数据库迁移或切换运行模式。

## 来源选择与启动边界

- FIXED：默认模式，使用固定定义及授权；意外安装 DATABASE 控制来源时明确启动失败，不因某个来源 Bean 存在而静默改用另一套授权。
- DATABASE：必须提供明确的授权解析器及恰好一个 `AiControlConfigurationSource`。缺失或多个来源均拒绝，`@Primary`
  不用于掩盖来源冲突；失败不回退文件 Grant／预算。
- 默认目录、预算、资格、政策和门控从同一模式选择来源。端口仍支持独立替换，自定义实现须遵守精确引用、当前资格及事务内同步方法契约。
- FIXED 继续验证静态定义完备性及固定 DeepSeek／协议绑定；DATABASE 的静态
  Grant、能力、绑定、连接、费率及预算列表可以为空，不为构造生产服务而创建固定控制面。部署环境参数和入口默认 releaseRef 仍保留配置。
- DATABASE 默认模型适配器在启动时只登记本地实现的生成 Schema 支持，不调用 `source.definitions()`、不查询发布表或解析凭据值。
  `supports` 检查已解析能力的 Schema、特性及状态，精确版本和可执行资格在运行时通过业务端口取得；不合成本地公共模型定义或远端探测结果。FIXED
  手工登记能力的旧构造器继续保留。
- 关闭 AI 时继续不要求这些运行依赖；构造运行组件不执行 DDL、初始化预算、创建 Run 或发起模型调用，Worker 是否运行仍由原开关控制。

动态模式在使用时缺少发布内容、兼容预算或当前资格会明确拒绝，不能凭部署文件种子开放旧权限。工作空间创建仍独立于 AI 模板；进入
AI 后按需准备的行为保持不变。

## 原事务发布读取

`PublishedAiCatalog.inCurrentTransaction(context, work)`
提供原同库写事务内的精确发布视图，补齐付费工具门控的同步目录读取。它只读取当前发布内容，调用方仍须组合公共授权、工具固定合同与预算资格，不能把目录读取当作写授权。

默认适配器在 `ControlConfigurationReader` 的同步范围内运行，与预算／政策读取共享本次当前配置；保留完整上下文、来源、事务标记隔离及异常清理。app
先取得公共父范围门控，再复核目录／预算，事务内没有异步阻塞或网络等待。只实现异步目录的自定义提供者在该写入路径默认拒绝，不退回旧配置对象。

`historicalRate` 继续是另一条内部精确读取路径：已有 Reservation
按原固定版本结算，当前调用资格失效不导致费用失去核对依据，也不能借旧费率重获新调用资格。金额、预留及未知费用证据规则沿用原实现。

## 兼容入口与保留边界

`FixedControlCatalog`
标记为兼容类型，保留旧构造器、常量及手工读取入口；其模型校验／解析和连接发送检查委托同一业务实现。旧服务构造器及政策／门控覆盖方法仍供手工装配和既有测试使用，生产配置走完整端口构造器。新代码应使用业务接口，不依赖旧具体
Bean 类型。

以下配置类型仍有明确用途：`NewAiProperties` 及其 Grant／Rate／Budget 继续用于文件绑定、发布 JSON 和迁移桥；
`AdmissionAuthorization`、`AiControlConfigurationSource`、操作准备／读取快照及来源适配器仍可在迁移边界解释这些记录。环境线程、HTTP
出口／连接池／帧上限和 SecretRef 环境映射继续属于部署参数。本批没有将所有配置转为数据库，也没有删除历史持久化类型。

未实现完整 HYBRID／DYNAMIC 来源登记、公共模型 ACL、个人凭据录入／用途治理、系统内部收尾或空间关闭闭环；本次“兼容验收”指当前
FIXED／DATABASE 控制面端口拆分的本地验证。文章及前端保持原范围。

## 验证

缺失／重复来源及缺失授权解析器；无静态种子的默认生成装配且启动零来源／数据库读取；无静态授权／模型／预算时通过受信来源完成真实
