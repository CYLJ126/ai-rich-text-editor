# TOOL 执行记录与统计（S6-02）

本批提供当前用户在当前空间的执行列表、样本统计和工具页“执行记录与统计”。复用现有身份、空间资格和
`ToolInvocationAccess.READ`，不授予管理员跨主体查询权，不新增执行、重试、扣费或结果核对入口。

## 1. 页面与接口

工具页打开“执行记录与统计”，默认最近 24 小时。可以按受理时间、稳定配置 ID、工具 ID 和状态查询，查看调用编号、
追踪编号、固定工具版本、来源、Attempt／重试、稳定错误码、费用和记录跨度。时间表单使用浏览器本地时区，提交为 UTC。 “最近 24
小时”重新固定当前窗口；普通刷新沿用表单窗口，便于观察原范围内的状态推进。

- 首次打开、查询、翻页和手动刷新才请求，不启动轮询，不因 UNKNOWN 自动调用工具。
- 切换账号／空间中止原请求；迟到响应或旧凭据响应不能写入新页面。凭据变化清除旧结果并允许重新查询。
- 页面明确显示已应用的窗口及筛选，编辑未提交的表单不改变已应用结果的含义。
- 未找到或无权限时不返回该调用；接口错误不显示假零统计。历史未回填或样本截断会显示警告。

外部前缀 `/arte/ai-new/tool`，内部 Controller 路径不含 `/arte`：

| POST 后缀        | 输入                                                             | 返回                                                                                                  |
|------------------|------------------------------------------------------------------|-------------------------------------------------------------------------------------------------------|
| `listExecutions` | scope、from、until、可选 bindingId／toolId／state、cursor、limit | 白名单记录、nextCursor、exhausted、scanned／scanLimit、historicalIncomplete、observedAt、query、scope |
| `getStatistics`  | scope、from、until、可选 bindingId／toolId／state                | 调用／Attempt／状态、成功率、费用、已知输入字节、跨度百分位及扫描／覆盖信息                           |

```json
{
  "scope": {
    "tenantId": "当前租户",
    "workspaceId": "当前空间"
  },
  "from": "2026-10-21T00:00:00.000Z",
  "until": "2026-10-22T00:00:00.000Z",
  "state": "UNKNOWN"
}
```

窗口必填、使用毫秒精度，按权威 `Invocation.acceptedAt` 的 `[from, until)` 筛选，最长 31 天。 这是受理记录的时刻，不是入口收到请求的
receivedAt 或数据库物理提交时刻。状态为本次查询读取到的当前事实， 不是窗口截止时刻的历史状态。`getStatistics`拒绝分页字段，两个接口均拒绝
subjectId／managed 等未知字段。

查询须具备 `ai:read`；每条记录另经当前工具历史读取资格检查，加载后和返回前分别复核。当前全局资格也重新检查。 HTTP
入口使用订阅内只读授权快照；返回前通过 `requireFreshRead` 重新取得当前只读资格，不复用入口快照， 也不调用写操作的
`requireWrite`。空结果同样复核；读取期间撤权则拒绝返回。只读快照仍禁止用于写入或派发。
工具历史资格使用有界批量接口，加载后与返回前各调用一次，批次不跨请求缓存。平台宿主逐条核对完整 owner， 同一用户／空间的账户、空间门控及
RBAC 规则相同，因此每阶段只读取一次公共资格，避免对每条记录重复持锁查询。 其他宿主默认仍逐条检查资源资格；执行层复核每份许可的调用编号、主体、空间、权限上限和期限。
现有取消及提交的事务内写授权规则不变；本接口仍使用最多 10 秒查询期限，不能靠延长工具执行期限解决查询超时。
停用新调用后仍可在原读取资格下查看历史。列表不返回参数、配置、授权快照、账户引用、远端地址或结果正文； 原结果／事件继续使用既有已授权
Invocation 读取接口，不建立第二套结果权威。

## 2. 有界分页与样本含义

- `scope` 固定返回 `CURRENT_SUBJECT`，完整 owner 来自当前可信上下文，不能通过管理权限或请求正文切换主体。
- 列表每页 1～20 条，默认 10；每次最多处理 50 个候选。统计最多处理窗口内最新 100 个候选。
- SQL 按 owner、受理窗口及可选 bindingId 走复合索引；按 accepted_at／invocation_key 倒序取候选，并多取 1 条判断后续。 不使用深
  OFFSET，不统计全表总数，不扫描完整工具执行快照。
- toolId／state 及当前工具可见性在候选内过滤。空页仍可能有 nextCursor，不能把空页当作已到末尾。 游标沿实际位置继续，绑定完整
  owner、窗口及筛选，跨空间、换条件、损坏或超长游标明确拒绝。
- `scanned` 是处理的候选数，多取的控制记录不计入。统计 `truncated=true` 表示还有候选未计入， 不能将
  invocations、费用或百分位称为窗口全量数据；可以缩小窗口或用配置 ID 的索引筛选。
- `historicalIncomplete=true` 表示当前主体有尚未回填的历史查询投影，即使没有扫描截断，也不能声称历史覆盖完整。
- 每批至多 20 条按主键加载 Invocation、全部 Attempt、审批及相关账本；同一批在短只读事务中取得一致事实。 不读取结果正文，不逐条查询账户总额，不按
  JVM 缓存推导统计。单批最终结算读取也有 2,000 条保护上限，超限报错，不伪装已知费用。
- 不冻结整个窗口，批次之间、列表与统计之间状态可能推进；`observedAt` 是本次查询开始的观察时间。
  本批提供运营查询，不承诺历史时点报表或财务报表的一致快照。

## 3. 指标口径

| 指标                             | 依据与限制                                                                                                                                    |
|----------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------|
| invocations                      | 通过当前读取资格且符合筛选的逻辑调用数；幂等重放不增计                                                                                        |
| attempts／retries                | 全部耐久 Attempt 数；重试为每调用 `max(Attempt 数 - 1, 0)` 的合计，不等同于调用量                                                             |
| states                           | 所有 Invocation 状态分别计数；UNKNOWN、等待审批及运行中不并入普通失败                                                                         |
| successRate                      | 成功数／已确定终态数，返回百分数字符串；分母包含 SUCCEEDED／FAILED／CANCELLED／TIMED_OUT／INTERRUPTED，排除 UNKNOWN 和非终态；无分母返回 null |
| FREE                             | 不计费，不创建虚构模型 Token 或工具账单；金额为 null，不与已知零费用的 CHARGE 混淆                                                            |
| SETTLED／RELEASED                | 本 Attempt 的最终 BudgetSettlement 是费用依据，币种与预留及存在的可信账单相互校验；允许业务仍 UNKNOWN、费用已确定                             |
| RESERVED／PENDING_RECONCILIATION | 展示原预留金额；settledAmount 为 null，unknown 为 true，预留不是实际消费                                                                      |
| NOT_RESERVED／缺少最终费用事实   | 不根据成功、失败或取消补零；费用未确定单列。缺失被引用的 Attempt／预留属于错误，不伪装未预留                                                  |
| currencies                       | 仅合计已确定部分费用及当前预留，按币种分别返回精确十进制字符串；未知部分未计入，不提供将其视为零的总费用                                      |
| knownZeroCostCalls               | 已有最终费用事实、金额确认为零的收费调用，不包含 FREE                                                                                         |
| inputBytes                       | 原标准参数值经紧凑规范化 JSON 编码的 UTF-8 字节数；不是 Token 或 HTTP 请求字节；回填历史无法可靠重建时为 null，未知项数单列                   |
| outputBytes／远端业务计量        | 当前没有独立的可靠查询投影，明确不可用；不读取完整结果来临时扫描，也不补零                                                                    |

阶段跨度均来自持久化记录，不将不同指标简单相加：

- admissionToAttemptMillis：受理至首次 Attempt 的跨度，可能包含审批、排队和授权。
- approvalWaitMillis：审批创建至决定／本次观察的跨度；没有审批时为 null。
- attemptSpanMillis：每次 Attempt 创建至其状态更新时间的跨度之和，进行中的 Attempt 使用本次观察时刻。
  包含网关和结果保存等时间，不等同于适配器实际执行时间。
- terminalSpanMillis：受理至当前终态更新时间，可能含核对；非终态为 null。
- P50／P95：仅对已确定终态的可用 terminalSpanMillis 按 nearest-rank 计算；UNKNOWN 不进入该分布。
- 跨节点时钟逆序返回 null，不夹成已知零。适配器实际运行、物理结果提交等独立阶段继续通过现有
  [P01 阶段日志与测量](TOOL_PERFORMANCE.md) 定位，本 API 不声称具有该粒度。

只统计 TOOL Invocation，聊天的模型生成子调用及其 Token 不混入。聊天工具子调用按原 parent 关联显示； S6-01 工作流消费当前仍按独立
TOOL 受理，本批不根据 ID 前缀虚构“工作流来源”或工作流根统计。

## 4. 数据库升级交付

新增 `accepted_at`、`observation`、`observation_digest` 及 owner／时间和 owner／绑定／时间两个索引， 均位于现有
`arte_ai_tool_execution_snapshot`。小型元数据在持锁前编码，随原快照 INSERT 同事务提交， 投影失败使原 Invocation／事件／DISPATCH
一起回滚；不增加独立受理写事务或第二条 INSERT。 原执行快照、持久化类型版本、工具定义及调度清单算法不变。

- 新库使用 `scripts/arte-ai-new-ddl-mysql.sql`；历史 S2-03 建表脚本同步相同结构。
- 已安装 TOOL 表的环境使用 [S6-02 增量 SQL](scripts/arte-ai-tool-observation-migration.sql)，不能重复运行原建表脚本。
- 部署方停写、备份、检查列及索引不存在后执行 **结构段一次**，统一升级相关应用节点。 中途 DDL 失败须先核查已完成部分，不能盲目重跑完整文件。
- 结构后单独重复执行 **回填段**，每批最多 500 条，直到 remaining_legacy_rows 为 0。 受理时间从对应 Invocation
  权威快照回填，不能用升级时间或 receivedAt 替代。 元数据仅从固定工具快照提取，原参数／配置不写入小型投影，历史 inputBytes
  保留未知。
- 回填期间原调用、审批和结果不改写；查询明确显示历史覆盖不完整。旧二进制写入的记录仍以 accepted_at=0 提示待回填，
  不能把有默认列当作允许长期混跑新旧版本的依据。
- 应用启动不执行 DDL、历史扫描或回填。本次只交付脚本，未连接部署数据库；MySQL 特定回填及大表索引成本须在部署环境验收。

## 5. 验证边界

`ToolObservationIntegrationTest` 使用临时 H2、真实受理／MyBatis／账本及 HTTP 白名单验证：幂等计数、Invocation／Attempt 区分、
免费／收费／零价／待核对、业务与费用状态分离、精确窗口及分页、当前授权与返回前撤权、跨空间隔离、样本截断、历史未回填、
投影损坏、同事务回滚、真实序列化路径和增量结构保留原数据。H2 结构测试只对多个 ADD COLUMN 的语法做拆分适配， 不将其作为 MySQL
原始 DDL、JSON 回填或生产查询计划验收。

HTTP 回归使用实现 `ExecutionReadAuthorizationResolver` 的解析器，实际安装入口只读快照，覆盖列表与统计、空结果、
返回前全局撤权及不进入写授权解析路径。聊天回归执行真实 Run／Invocation 流程，确认工具子调用可读取、模型调用不计入工具统计。

前端验证查询、分页、截断与历史告警、金额精度、空间迟到响应、凭据变化、异常提示及现有工具页回归。
具体计数、全量类型检查基线和限制见 [实施记录 §49](TOOL_IMPLEMENTATION.md#49-s6-02执行列表与有界统计)。
本批不包含跨用户管理员报表、导出、长期聚合表、工作流编排或 S6-03 的生产故障／多节点／性能验收。
