# AI TOOL S3-05：人工业务结果核对与界面

更新：2026-10-20。基于 S3-04 原工作项实现当前空间责任池、本人进度、独立认领、权威证据复验、无法判定记录和超期提醒。
当前正式证据验证器只支持 `workspace.updateDetails@v1` 的原领域命令回执；不重新执行工具、不改变操作键、不创建新的
Attempt、不调用模型、不修改预算。 写工具和核对开关仍默认关闭；本批没有执行业务库 SQL、修改运行配置、发布工具或重启应用。

## 用户流程与授权

普通调用者通过 `aiTool:list` 及当前空间读取资格查看 **本人**原调用的核对进度。UNKNOWN 调用卡片直接展示进度，工具页另有“结果核对”页签。
详情展示检查次数／截止、责任方、下一步、处理截止；没有认领时责任方为“当前空间核对责任池”，提示联系空间负责人。
没有目录／本人读取资格、跨主体或跨 Scope 的请求不会返回原内容。

处理责任池需要 **显式 `aiTool:reconcile` + 当前空间 `WORKSPACE_UPDATE`**，沿用现有公共成员治理；该动作目前允许当前
OWNER／ADMIN。 与原工作空间信息写工具的管理范围一致，没有新增身份、角色或资源动作，没有修改公共角色权限。 菜单 `admin` 标记、
`aiTool:approve`、预算管理或普通调用权均不替代核对资格；关闭空间 AI 新调用不会自动取消必要收尾资格。
所有读取及命令重放重新授权，真正提交在原物理事务再次核验账户、成员、操作及治理资格，锁保持到事务结束。

当前只支持“认领给本人”，认领者本身须有当前核对资格；再次认领须提交最新版本、原因和下一步，作为有审计的责任交接。 确认和
UNRESOLVABLE 必须由 **已认领且不是原发起者**的主体提交。没有合格的独立复核人员时保持待处理并告警，不提供自审例外。
责任方的稳定主体编号用于定位，具体联系安排填写在“下一步”。不自动授予角色或指派无资格人员。

管理员不因当前空间权限获得私人正文读取权：对尚未通过独立历史契约验收的工具，管理详情隐藏原参数。
当前受信工作空间工具只展示本次空间元数据参数；其他工具须先实现其资源范围／材料披露验证器，不能直接套用此映射读取文章或私人文本。
本人读取仍按原归属显示本人的参数，人工审计仅在管理视图返回。

## 证据与状态

1. 独立人员先认领原工作项，填写原因及下一步，再点击“核验原领域回执”。该操作只读取原回执，不消费或重置自动检查额度。
2. 系统从 `CommandReceiptStore.findCurrent` 重建原操作证据，核对原 subject、Scope、命令类型、操作键、参数摘要、结果
   Schema、状态及版本。 页面按文本展示证据引用、摘要和精确 JSON，人工填写核验记录并二次确认。
3. `confirmOutcome` 在短事务内 **再次读取权威回执**，比对本次提交的结论、引用、摘要、副作用及完整输出；页面先前读到的材料不能替代提交复验。
   结果继续通过原固定 Schema／输出字节上限、owner、callId、Attempt、版本及 fencing 检查。
4. 人工和自动完成共用结果／证据／原终态／事件提交逻辑；人工责任记录及命令审计也在该物理事务内。 审计插入失败回滚全部完成事实。原
   UNKNOWN 结果保持不可变，确认结果使用独立结果槽；领域回执与业务数据不再修改。

当前领域回执只证明已提交成功；查无回执不证明未执行或失败。无法判断时记录原因、下一步和 UNRESOLVABLE，原 Invocation 仍
UNKNOWN， 不释放虚构费用，不提供重新执行原写操作。后续取得可靠证据可再次由独立责任人核验，按最新版本收敛。

`VERIFIED_BUSINESS_RECORD` 仅为保留的来源标记，当前没有经过审核的外部记录验证器，提交会明确拒绝。
普通调用者、模型／浏览器文本、手填金额、无来源截图或任意“确认成功”不作为证据。后续外部工具需要独立实现可信记录查询与资源范围校验，
不能仅放开来源枚举接受人工自报结果。本批不宣称远端／外部记录核验已实现。

同键同意图返回原命令回执，同键异义拒绝；新命令过期版本拒绝。已经确认的相同事实不重复创建结果或证据，返回 ALREADY_RESOLVED。
如果权威证据与原已确认结果冲突，保存 EVIDENCE_CONFLICT 审计并进入 NEEDS_REVIEW，继续显示责任方及下一步，不覆盖原已确认终态。
这不是允许通过相反结论改写已生效业务的入口。

## 竞争、额度与提醒

自动领取与人工命令共用原 Invocation／Case／Attempt 锁及版本；后台活跃租约期间不能人工抢占。 原 RECONCILE Attempt
仍有活跃租约时等待其结束。人工决定会获取原 Attempt 的新 RECONCILE fencing；不新建执行、不 markDispatch。 人工核验可在原执行
deadline 和 30 分钟自动窗口之后处理，使用新的短事务资格，不恢复原工具执行权。

`requestOutcomeCheck` 仅记录一个有幂等键的查询意图，原可靠工作项继续按既有后台轮询、下一检查时间和容量运行。 不提前
next_check、不延长 valid_until、不清零六次额度、不恢复 NEEDS_REVIEW／UNRESOLVABLE；到达限额返回 NEEDS_REVIEW。
它没有“重新执行”语义，也不会因浏览器刷新而额外生成查询。

责任处理截止固定为原自动窗口截止加 24 小时，认领、重放和重复请求不顺延。 后台每轮最多检查 100 个需处理项，对未认领或超期项输出安全
`AI_TOOL_REVIEW_ATTENTION` 告警；同项最少间隔五分钟，告警时间持久化。 告警内容仅含原编号、状态及未认领／超期标志；界面同步显示超期及处理入口。本批没有外部邮件／消息发送。

列表按空间索引与主键游标分页，每页最多 20 条，默认显示未 RESOLVED 的任务，完成记录可按原编号恢复。
每条详情在独立短事务重新授权，避免持治理锁后再锁下一条 Invocation；审计展示最近 50 条，不承诺一次返回全部历史。

## HTTP 与浏览器恢复

全部 POST `/arte/ai-new/tool/`，同现有工具接口使用严格白名单；所有写入要求 `Idempotency-Key`。

| 后缀                    | 用途                                                                      |
|-------------------------|---------------------------------------------------------------------------|
| getReconciliation       | scope、invocationId、managed；默认本人进度，managed=true 要求核对管理资格 |
| listReconciliations     | 当前 Scope 责任池，cursor／limit                                          |
| claimReconciliation     | 认领到当前合格主体，版本／原身份／原因／下一步                            |
| requestOutcomeCheck     | 复用原有界工作项，不重置检查额度                                          |
| getOutcomeEvidence      | 已认领独立人员读取原权威领域证据                                          |
| confirmOutcome          | 独立责任人提交已核验的原证据，服务端复验后原子提交                        |
| markOutcomeUnresolvable | 保留原 UNKNOWN，记录无法判定及下一步                                      |

命令包含 `invocationId`、`attemptId`、原 `operationKey`、字符串 `expectedVersion`（Case）、字符串
`expectedInvocationVersion`、`reason`、`nextStep`。confirmOutcome 另包含
evidence：source、decision、reference、digest、sideEffect、
`outputJson`、`verificationNote`；其他命令不得携带证据。版本不经过 JS Number，输出 JSON 作为字符串传输并在服务器按精确数字解析。
不接受 actor、owner、roles、预算、费用、执行次数或任意 URL。

浏览器先将原命令、完整参数和键保存在账号／空间／原调用隔离的 sessionStorage，再发送；存储失败不发送。
网络或超时结果不明时只允许确认原命令；刷新恢复原键，不反向决定。服务端明确 400／409 拒绝后要求刷新并重新核验，不能陷入永远不明。
权限／账号变化会停止读取与新决定；组件卸载只取消浏览器等待，不撤销已经提交的服务器命令。旧账号／空间响应不会落入当前界面。
所有原参数、证据和审计只按文本展示，不执行 HTML 或跳转未知证据 URL。

## 部署

全新库执行更新后的完整 `arte-ai-new-ddl-mysql.sql`，不要重复运行增量。 已有 S3-04
库停止新受理及相关消费者、备份后，显式执行 [人工核对增量](scripts/arte-ai-tool-review-migration.sql)：
新增责任表、不可变人工命令表及空间分页索引；原核对状态、计数、期限、证据和业务／费用事实不重置。 缺少 S3-04
三张基础表时先按 [自动核对说明](TOOL_OUTCOME.md) 安装。运行时不建表、不用 IF NOT EXISTS 掩盖结构漂移。

再部署 [RBAC 定义脚本](../arte-app/scripts/arte-ai-tool-rbac-dml-mysql.sql)；仅补 `aiTool:reconcile` 等缺失定义，保留已有停用和版本。
通过既有 RBAC 管理向合格人员显式授予工具菜单及核对操作，本脚本不自动授予用户或角色，RBAC 完整基线已同步。
共享数据库的节点／消费者统一升级，保留相关基础 Worker 和核对开关处理既有事实。

继续使用 `arte.ai-new-tool-outcome.enabled=true` 开启核对接口及后台；自动处理和提醒还需要原 worker-enabled=true。 原
AI／TOOL／执行、分类调度和同构清单条件仍适用。写工具开关独立，关闭新写入口不取消已有核对。 本批不改变已发布 v1 契约、TOOL
清单、原审批规则或现有聊天预算。
