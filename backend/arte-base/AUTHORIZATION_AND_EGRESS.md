# 授权与资料外发契约

依据顶层设计的公共授权／外发端口、资源动作边界和安全护栏定义本批操作。生产代码仅依赖 JDK，旧 core、旧 AI 和 app 的引用及接线保持不变。

本模块提供请求、决策和强制检查规则。[app 新接入层](../arte-app/SECURITY_BRIDGE.md) 已补充现有主体认证、持久化成员关系、资源共享、
应用／绑定及任务权限、用户同意与策略版本存储；真实网络出口仍由后续连接运行时实现。值对象或允许决策本身不是可从客户端提交的授权凭证。

## 操作

| 端口                 | 方法                                | 含义                                               |
|----------------------|-------------------------------------|----------------------------------------------------|
| AuthorizationService | evaluate(AuthorizationRequest)      | 核对一项资源动作，返回绑定完整请求的预检／解释快照 |
| AuthorizationService | requireAuthorized(request[, Clock]) | 每次重新调用提供者，在操作边界强制检查             |
| EgressPolicy         | evaluate(EgressRequest)             | 核对完整实际外发范围，返回绑定完整请求的快照       |
| EgressPolicy         | requireAllowed(request[, Clock])    | 每次重新调用提供者，在发送边界强制检查，不发送数据 |

无时钟参数的强制方法使用 Clock.systemUTC；带 Clock 的方法便于注入时间及确定性测试。当前端口为同步判定契约，不暴露
Spring、安全框架或数据库类型；后续需要外部策略服务时，由实现层安排适用的 I/O 执行方式。

evaluate 正常拒绝返回 DENY，无法确认返回 INDETERMINATE，不返回 null。调用方不能把预检快照直接当作后续操作许可。require
方法只在完整请求匹配、时间窗口有效且结果为 ALLOW 时正常返回。

## 资源授权

AuthorizationRequest 包含发起者的 ExecutionContext、实际执行主体 executor、ResourceRef 和 actionCode。actionCode
保存扩展动作码的字符串快照；公共动作以 CommonResourceAction 枚举提供，领域可实现 ResourceAction 扩展。

公共动作分别覆盖阅读、标注、评注、编辑、共享管理、导出、复制、AI 处理、外发、事件订阅和产物下载。动作不表达角色继承关系：阅读不隐含
AI 处理或外发，编辑不隐含共享管理，平台运维身份不自动获得内容权限。

直接调用时 executor 与发起者相同；Worker 可以传入受限服务主体。构造仅限制不同执行者必须是
SERVICE，实际服务身份与委托关系仍须由接入层验证。提供者必须将服务主体权限与原发起者、租户／空间、资源共享、应用／绑定及任务授权取交集，不以服务身份或任务声明扩大权限。

AuthorizationService 的提供者须核对当前租户／空间归属、资源动作及策略；领域版本、草稿摘要、范围有效性和业务规则仍由资源领域检查。未知领域或无法核对不允许回退到全局角色许可。

## 资料外发

EgressRequest 包含：

- 发起者上下文及实际执行主体。
- 完整实际资料来源 sources 的不可修改副本；用户消息独立运行时可为空，但仍须经过策略判定。
- 已解析且固定版本的 EgressDestination。
- 稳定用途标识 purpose 及完整实际业务内容摘要 contentDigest。
- 可选 consentRef，指向用户确认记录或适用设置；提供者核对其归属、有效性及覆盖范围。

sources 只列实际发送的业务资料；contentDigest
由服务端对最终准备发送的业务内容生成，覆盖用户消息、实际片段、派生摘要、任务指令及适用工具内容，不包含认证请求头。摘要生成、规范化和实际发送内容一致性由调用方保证，不能信任客户端自报摘要。

EgressDestination 使用固定正式版本的公共连接引用，不能使用当前连接或草稿。origin 只包含 HTTP (S) 协议、主机和端口，不接受
API 路径、参数或凭据；协议／主机转为小写，默认端口和根路径统一表示。非默认端口和连接版本仍参与匹配。

API 路径、认证参数与实际连接操作来自受控连接配置，不通过 EgressRequest 自报。origin
的结构校验不证明地址安全：DNS、私网及元数据地址、受批准内网、重定向、最终地址和网络出口检查须由连接运行时在真实连接边界完成。

外发必须同时满足资源读取／处理授权、资源共享外发策略、任务范围、用户同意及用途／目的地策略。consentRef
存在不等于已获同意，采纳内容不等于同意训练或其他二次使用。

外发判定覆盖完整集合，不提供静默的部分允许。如果资料、用途、摘要、确认引用、主体、连接版本或目的地变化，必须重新准备请求并重新评估；实际发送不得与已核对请求不同。

新 AI 链路的调用顺序：

1. 读取业务资料时，对每个资源执行 READ 授权并验证版本／草稿／范围。
2. 最终资料范围确定后，对实际来源分别检查 AI_PROCESS 与 EGRESS；仅有用户消息时仍检查执行主体、任务及绑定权限。
3. 从受控连接配置解析目的地，基于最终业务内容计算摘要，构建 EgressRequest 并调用 requireAllowed。
4. 连接运行时验证实际目标地址和出口，再发送一致的内容；重定向或目的地变化时重新执行适用的外发及出口检查。

此顺序由后续 AI 执行协调和组合层落实，不要求 AI 创建文章或依赖文章实现。

## 决策与强制检查

AuthorizationDecision 与 EgressDecision 分别绑定各自完整请求，共享 PolicyDecision：

| 字段           | 约束                                                                           |
|----------------|--------------------------------------------------------------------------------|
| outcome        | ALLOW、DENY 或 INDETERMINATE                                                   |
| reasonCodes    | 不可修改的稳定原因码集合；拒绝／无法确定必须提供原因，不携带正文或自由错误文案 |
| policyVersions | 不可修改的实际检查策略 ID／版本快照；ALLOW 必须非空                            |
| evaluatedAt    | 必填，由提供者记录                                                             |
| validUntil     | ALLOW 必填且晚于 evaluatedAt；达到此时刻即失效                                 |

有效期由提供者策略确定，按顶层设计评估短期权限租约（建议不超过 5 秒）；base 不在数据构造中固定全平台期限。isAllowedAt
只检查快照窗口，不核对权限撤销或策略当前版本。

强制方法在评估前检查执行期限，返回后再次检查执行期限、决策时间及完整请求绑定。提供者须逐次检查当前策略版本与撤销状态；活跃输出批次和长任务后续操作在各自边界再次调用强制方法。策略版本快照不是永久授权，发布清单不能覆盖紧急撤销。

| 情况                                         | 强制检查结果                                         |
|----------------------------------------------|------------------------------------------------------|
| 匹配且未失效的 ALLOW                         | 正常返回本次决策，随后进入领域事务或实际发送边界     |
| DENY                                         | BaseException，错误码 arte.common.unauthorized       |
| INDETERMINATE、null、提供者 RuntimeException | BaseException，错误码 arte.common.policy_unavailable |
| 请求不匹配、决策已过期或来自未来时间         | BaseException，错误码 arte.common.policy_unavailable |
| 执行期限已届满，包括评估期间届满             | BaseException，错误码 arte.common.deadline_exceeded  |
| 请求／Clock 的结构不合法                     | IllegalArgumentException，不调用提供者               |

没有隐式允许或空实现。提供者异常 cause 仅供内部诊断，公开 ExecutionError 不回显异常文案。policy_unavailable
的可重试性只针对重新进行策略检查，不表示可以重放此前完成的业务或远端副作用；运行时仍须保留已发生操作的事实。

强制检查正常返回不代表执行、保存或外发已经完成，也不消除检查与实际操作之间的竞态。具体实现要在领域事务、条件写入或实际发送边界落实当前版本、授权及数据一致性。

## 后续接入与验证

app 已实现可单独启用的现有身份、个人 Tenant／Workspace 映射以及资源／外发策略提供者，增量表、启用条件及真实库适配测试见
[接入说明](../arte-app/SECURITY_BRIDGE.md)。下一步在新 AI 协调和连接链路中调用这两个端口。 旧入口与引用仍保持原样，没有自动迁移旧权限校验。

在 backend 下执行：

```bash
mvn -o -pl arte-base,arte-ai-new -am test
```

新增测试覆盖独立动作判定、拒绝与策略不可用、实时重新评估后的撤销、跨主体／资源／版本复用、完整外发范围及部分来源不匹配、资料防御性复制、目的地规范化、提供者耗时导致的期限／决策过期，以及错误诊断分离。测试使用可控策略替身，不证明真实权限库、网络出口或多实例撤销已经接入。
