# 如何开始：部署你的 ARTE

ARTE 使用 Docker Compose 部署。准备好 Docker 和项目文件，修改配置后即可启动配套服务；不需要在宿主机另外安装 Java、Node.js 或数据库。从源码构建时，编译也在容器内完成。

> **新装前请注意：** 当前源码可以启动服务，但尚未提供首个管理员初始化流程。全新实例请先与维护者确认账户初始化方案，再安排正式使用；已有可用账户的实例可继续按下文操作。详见[首次登录](#start-account)。

## 1. 准备环境和项目文件

需要 Docker Engine 或 Docker Desktop，以及 Compose V2。先确认两个命令都能正常返回版本信息：

```bash
docker version
docker compose version
```

建议为 Docker 留出 8 GB 左右可用内存和足够的磁盘空间。这是单机试用的起步建议，不是性能保证：默认后端与 Elasticsearch 的 Java 堆上限分别为 2 GB 和 1 GB，此外还有数据库、缓存、图表服务和容器构建开销。Windows/macOS 上还要检查 Docker 虚拟机的内存额度。

本机体验不需要域名。供其他人通过公网访问时，再准备域名、HTTPS 和反向代理。

获取完整仓库并进入部署目录：

```bash
git clone https://github.com/CYLJ126/ai-rich-text-editor.git
cd ai-rich-text-editor/deploy
```

也可以下载仓库 ZIP，解压后进入其中的 `deploy` 目录。后续命令均在该目录执行；从源码构建需要保留同级的 `frontend`、`backend` 等完整项目文件。

## 2. 先配置，再启动

首次安装且还没有 `.env` 时，复制配置模板。已有实例直接编辑原 `.env`，不要覆盖。

Windows PowerShell：

```powershell
Copy-Item .env.example .env
```

Linux / macOS：

```bash
cp .env.example .env
```

用文本编辑器打开 `.env`。本机体验先设为：

```dotenv
ARTE_BIND_ADDRESS=127.0.0.1
ARTE_PORT=8000
```

这会让入口只监听本机。如果 `8000` 已被占用，修改 `ARTE_PORT` 即可，不用改容器内部端口。局域网访问需要改为主机可访问的绑定地址，并按需配置防火墙。

首次启动前一并修改这些配置：

| 配置 | 要做什么 |
| --- | --- |
| `MYSQL_ROOT_PASSWORD`、`MYSQL_PASSWORD` | 分别设置数据库 root 与应用用户密码 |
| `ELASTIC_PASSWORD` | 设置 Elasticsearch 密码 |
| `JWT_BASE64_SECRET_KEY` | 换成足够长的随机 Base64 签名密钥，不要继续使用示例值 |
| `JWT_DEFAULT_PASSWORD` | 修改用户创建逻辑使用的默认密码；它不会创建首个管理员 |
| `SECURITY_SM2_PRIVATE_KEY`、`SECURITY_SM2_PUBLIC_KEY` | 换成配套的 SM2 密钥，不能分别填写两个随机字符串 |
| `ARTE_VERSION` | 使用发布镜像时，填入实际已发布的标签；正式环境固定版本 |
| `JAVA_OPTS`、`ES_JAVA_OPTS` | 按主机资源调整 Java 内存，给其他服务留出余量 |

`.env` 含有秘密配置，不要提交到 Git，也不要截屏公开。修改 JWT 密钥会影响已有登录令牌；已有数据库的密码也不能只改 `.env`，还要同步修改服务中的实际凭据。

> **[待补步骤 S03｜当前版本的密钥生成方法]**
> 正式发布安装指南前，请由维护者补充在本地生成 JWT 随机密钥和匹配 SM2 密钥对的实际命令，写明依赖、输出编码与三个配置项的对应关系，并验证登录加解密正常。此处不填写生成后的私钥或可复用秘密，也不要让读者到在线生成网站提交秘密。未确认方法前，只在隔离的本机环境验证部署，不开放公网。

AI 模型可以在登录后配置，此时无需填写 API Key。`DEEPSEEK_API_KEY` 是可选的进程级默认值，不是启动写作功能的前提。

检查配置格式：

```bash
docker compose config --quiet
```

无错误退出表示 Compose 配置能够解析，不代表镜像已发布或数据库连接已成功。

## 3. 启动服务

两种方式选一种即可。

### 使用已发布镜像

适合运行指定发布版本。默认从 GHCR 拉取镜像，需要所选标签已经存在并具备拉取权限。

Windows PowerShell：

```powershell
.\compose-up.ps1
```

Linux / macOS：

```bash
bash ./compose-up.sh
```

### 从当前源码构建

需要运行本地修改、仓库最新代码，或尚无可用发布镜像时，使用此方式。

Windows PowerShell：

```powershell
.\compose-up.ps1 -BuildLocal
```

Linux / macOS：

```bash
bash ./compose-up.sh --build-local
```

首次构建需要下载基础镜像和依赖，耗时取决于网络与主机性能。源码构建不等于离线安装；它可以避开尚未发布的 ARTE 镜像，但仍需访问构建依赖。

脚本会启动服务并等待健康检查，等待上限为 900 秒。出现 `AIRichTextEditor is ready` 后，在部署主机打开 [http://localhost:8000](http://localhost:8000)。如果改过端口，使用相应端口；远程服务器上的 `localhost` 指服务器本身，不是你的电脑。

### 这些容器分别做什么

| 服务 | 用途 | 默认访问方式 |
| --- | --- | --- |
| frontend | 网页和反向代理入口 | 主机 `8000` 端口，映射到容器 `8080` |
| backend | 文章、用户、AI 等业务接口 | 由 frontend 转发，位于容器网络 |
| mysql | 业务数据 | 容器网络 |
| redis | 缓存与异步处理状态 | 容器网络 |
| elasticsearch | 全文与向量检索 | 容器网络 |
| drawio | Draw.io 图表编辑器 | 由 frontend 转发 |

Kibana 默认不启动。只想使用文档功能，不必额外开启它。

## 4. 确认能正常使用

先看运行状态：

```bash
docker compose ps
```

应能看到六个核心服务启动，其中 MySQL、Redis、Elasticsearch、backend 和 frontend 配有健康检查；Draw.io 没有配置同样的检查，显示运行中不等于图表编辑已经验证成功。

需要排查时再看对应服务日志：

```bash
docker compose logs --tail=100 backend
docker compose logs --tail=100 elasticsearch
```

### 首次登录

当前仓库的 `deploy/mysql/sql/arte-rbac-dml-mysql.sql` 没有预置管理员数据；前端注册页调用的是 `/api/register`，后端没有对应的注册实现。用户管理中的“新增用户”又需要已有权限，因此不能靠打开注册页完成首个账户创建。

全新安装请在此暂停，向维护者取得针对当前版本确认过的初始化方案。不要使用猜测的默认账号，也不要反复删除数据卷重装。`JWT_DEFAULT_PASSWORD` 只是默认密码配置，不代表数据库里已有用户。

已有可用账户时，登录后做一次小范围检查：

1. 若账户使用维护者提供的初始密码，先在账户安全设置修改密码并重新登录。
2. 在“我的空间”建一个测试目录，新建文章，写入标题与一段正文。
3. 保存并重新打开，确认内容存在。
4. 上传一张无敏感信息的图片，保存后刷新，确认仍能显示。
5. 用正文中的关键词搜索文章。索引异步更新，刚保存的内容可能需要稍等。
6. 插入一张 Draw.io 图表，保存后再次打开编辑。
7. 需要 AI 时，再进入模型配置，测试连通性，用测试文字尝试摘要或问答。

## 5. 按需补充配置

### 域名与 HTTPS

公网访问的入口指向 frontend，不要把 MySQL、Redis、Elasticsearch 等端口直接开放到公网。

如果反向代理运行在同一台主机上，可以保留 `ARTE_BIND_ADDRESS=127.0.0.1`。下面是放进**已配置域名和 TLS 证书的 Nginx `server` 块**中的片段，不是完整 HTTPS 配置：

```nginx
client_max_body_size 50m;

location / {
    proxy_pass http://127.0.0.1:8000;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_read_timeout 3600s;
}
```

反向代理如果也在容器里，`127.0.0.1` 指向代理容器自身，须改为它实际可达的 frontend 地址。代理需支持 WebSocket，才能传递文章版本变化提醒；长连接超时也会影响 AI 流式回复。

上传大小同时受外层代理、`NGINX_CLIENT_MAX_BODY_SIZE`、后端和前端限制。只改外层的 `50m`，不保证更大的文件就能上传。

### Kibana

要查看 Elasticsearch 的索引和运行信息，可以启用可选组件。

```powershell
.\compose-up.ps1 -Observability
```

```bash
bash ./compose-up.sh --observability
```

源码构建模式再分别加 `-BuildLocal` 或 `--build-local`。启用前设置独立的 `KIBANA_PASSWORD` 和三个 `KB_*` 加密密钥。Kibana 默认只监听本机 `5601`，无需向普通文档用户开放。

### 上传文件存储

Compose 默认使用本地存储，上传内容位于 `backend-uploads` 持久卷。项目还支持七牛云 Provider，但切换配置不会自动搬运旧文件。已有资料迁移到对象存储前，应先确认资源复制和旧链接处理方式。

## 6. 停止、更新与备份

普通停止使用以下命令，命名卷会保留：

```bash
docker compose down
```

**不要加 `-v`。** 这个参数会删除本 Compose 项目的命名卷，其中包含数据库、索引、上传文件等数据；没有备份就可能无法恢复。

更新前先备份，记录当前版本与配置。发布镜像模式先在 `.env` 中改为目标标签，再执行：

```bash
docker compose pull
docker compose up -d --wait --wait-timeout 900
```

源码构建模式更新到确认过的代码版本后，重新执行第 3 节带 `-BuildLocal` 或 `--build-local` 的启动命令。不要用一次普通镜像拉取替代本地代码构建。

备份至少覆盖：

| 内容 | 注意事项 |
| --- | --- |
| MySQL | 使用一致性数据库备份；不要把运行中随意复制的数据目录视为可靠备份 |
| `backend-uploads` | 图片和附件与数据库一起保存，避免恢复后只剩正文链接 |
| `.env`、Compose 文件、代码或镜像版本 | 秘密配置加密存放，记录能够重新部署的准确版本 |
| Elasticsearch | 使用适当的快照方案；只有验证过重建流程后，才可依赖重建索引 |

卷的实际名称可能带项目名前缀，用 `docker compose config --volumes` 和 `docker volume ls` 核对。Compose 还持久化 `redis-data` 与 `backend-logs`，按缓存任务恢复和日志留存需要纳入备份。

升级后重新检查登录、文章保存、图片、搜索和图表。如果数据库结构已经变更，退回旧镜像不一定足够，还需要恢复兼容的数据备份。第一次正式使用前，最好在独立环境恢复一次，确认备份真的可用。

## 7. 常见问题

### 等待超时，该看哪里？

先用 `docker compose ps` 找出异常服务，再看该服务日志。重点检查内存、磁盘、依赖下载和连接凭据，不要直接删除数据重装。

### 拉不到镜像，能改成本地构建吗？

可以，但要先分清原因。标签未发布或 GHCR 拉取权限不足，可选择实际可用的版本，或使用完整源码构建。Docker 基础镜像下载出现 `EOF`、超时等网络错误时，本地构建也可能失败，需要检查 Docker Engine 自己的代理与网络。

### 改了密码或初始化 SQL，为什么没生效？

MySQL 的初始化脚本只在空数据卷首次启动时执行。已有库不会因重启自动重新初始化，修改 `.env` 也不会自动修改已有数据库账户的密码。应先备份，再按目标变更执行迁移或修改凭据。

### 旧版 `nip` 数据怎么处理？

仓库提供 `deploy/mysql/migrate-nip-to-arte.sql` 供迁移审核。它不是新装步骤，也不保证适用于每个旧实例；先核对现有版本、数据库与附件路径，在备份副本上验证后再处理正式数据。
