# ARTE · 你的文档，你的知识库

把笔记、图表和团队手册，放进自己部署的在线文档里。

ARTE（AI Rich Text Editor）是一套可私有部署的开源文档系统。用富文本或 Markdown 写作，把代码、公式、图表和演示视频放在同一篇文章里；写好的资料可以整理、搜索、分享，也可以作为 AI 助手的知识来源。

## 一篇文档，写得下整个项目

安装步骤用任务列表，配置项用表格，启动命令用代码块。讲清服务之间的关系，可以直接插入 Mermaid 或 Draw.io 图表；需要演示操作，就把录屏放在对应步骤下面。

图表不必在改动后重新截图。打开正文中的图，修改源码或节点，再保存即可。方案调整了，文档也能跟着更新。

习惯 Markdown 的人，可以在源码和富文本之间转换，用分屏检查排版；习惯直接编辑的人，在空行输入 `/`，就能插入表格、代码、图片或图表。

> 在测试文章空行输入 `/`，选择 Mermaid，粘贴“编写 → 审校 → 发布”的三节点流程图并确认；再打开图表，把“审校”改为“同事审校”并保存。录下菜单入口、生成结果和再次编辑三个动作，末尾停留 2 秒。

## 写完以后，也找得到

个人草稿留在“我的空间”，共同维护的资料放进分享目录，面向读者的手册发布到“公共空间”。目录负责分类，标签把分散在不同目录的同类内容串起来。

想找上个月记下的一条命令？按标题、正文、作者或标签筛选。不记得原句，也可以试试相关性搜索，用自己的话描述要找的内容。

需要同事看一眼时，把文章或整个目录分享给对方。读者查看内容，审校者在原文旁留下批注，维护者修改正文；历史版本可以用来检查改动前后的差异。

## AI 可以帮忙，但不替你做决定

需要时，让 AI 续写一段说明、翻译选中文字，或为长文生成摘要。结果合适再采用，不合适就继续自己写。

也可以配置一个“项目运维助手”，启用文章知识库，再问“升级前要备份哪些数据？”助手会结合检索到的资料回答。重要命令和结论仍由你核对。

模型由你配置。不接入对话模型，也可以先使用写作、目录整理、图表和分享功能。接入外部模型时，相应文本与检索片段会发送给该服务；私有部署并不等于外部 AI 请求也留在本机。

## 从一份自己的手册开始

你可以把 ARTE 用作个人技术笔记、家庭服务器运维手册，也可以和几位同事一起维护产品文档。先建一个目录，导入两三篇已有 Markdown，再补上第一张图，比从空白知识库开始更容易上手。

应用、数据库和上传文件可以部署在自己的主机上。Docker Compose 提供配套服务，Markdown 导入与导出方便继续使用已有资料。备份时，数据库和上传文件要一起保留。

**先放进一篇你明天还会用到的文档。**

## 素材补充说明（发布前删除本节）

上面的三个素材框是拍摄说明，不是已完成的截图。请用真实 ARTE 界面制作；不要用示意设计图代替实际功能效果。

1. 在 `docs/public/assets/captures/` 中保存图片或 GIF，使用各占位框指定的文件名。先制作 I01 和 I02，主图与一次真实操作最能帮助读者理解产品。
2. 用 PixPin 截取应用区域；录 GIF 时只保留一条短操作，裁去等待和无关切换。隐藏通知、账户资料、密钥与内部地址。录制前准备好示例内容，避免长时间输入。
3. 用下面的 Markdown 替换整个 I01 占位框，另两个素材同理；图注另起一段保留。

```markdown
![ARTE 工作区：左侧目录、中间正文、右侧章节导航](assets/captures/i01-workspace.png)

*目录、正文与章节导航，在同一个工作区。*
```

4. 发布到 ARTE 网页时，本地相对路径不会自动变成服务器资源。将光标放到原占位处，通过图片入口上传 PNG/GIF，设置描述文字，再删除占位框。GIF 上传后在阅读模式确认会播放。
5. 网页中的两篇关联文章分别对应“全部特性”`articleId=119`、“如何开始”`articleId=120`，发布时将本地 `.md` 链接改为对应文章链接。章节锚点需按网页实际生成的链接重新复制。

三张素材就位后，先看首屏是否能认出这是文档产品，再检查字是否清楚、动图是否能看懂。不需要再加一张重复功能清单的装饰海报。
