## 1. 先理解 ARTE 的工作方式

ARTE 围绕“目录—文章—知识库”组织内容：

1. 在空间中建立目录，确定内容归属。
2. 在目录下创建文章，用富文本或 Markdown 编写正文。
3. 使用标签、封面和摘要补充文章信息。
4. 将目录或文章分享给其他成员，或发布到公共空间。
5. 保存后的内容异步建立搜索索引；文章问答和知识库助手按各自方式读取正文或检索片段。
6. 通过历史版本、批注和权限继续维护内容。

后文用“产品手册”作为示例：《安装指南》练习代码、表格和架构图，《常见问题》练习检索与问答，《版本记录》练习审校和差异对比。先在自己的空间起草，需要审校时分享，面向读者时再发布。

开始练习前，请使用已有可用账户，确认自己拥有测试目录的编辑权限。AI 示例还需要可用模型；分享示例需要第二个测试账户。不具备这些条件时，可以先完成写作和排版部分。

## 2. 空间、目录与文章管理

### 2.1 三种内容空间

写作页面左侧目录栏包含三个空间：

| 空间 | 用途 | 常见场景 |
| --- | --- | --- |
| 我的空间 | 当前用户自己的目录和文章，默认私有 | 草稿、个人笔记、尚未发布的文档 |
| 与我分享 | 其他用户或角色授权给当前用户的内容 | 参与维护团队手册、阅读内部规范 |
| 公共空间 | 集中展示已公开的目录和文章 | 使用指南、公共知识库、示例内容 |

“与我分享”不是内容副本。它仍然指向原目录或文章，能执行哪些操作取决于分享者授予的权限。如果希望形成自己的副本，可以使用“复制到我的空间”。公开内容是否允许未登录访问，需要结合实例的公开配置检查，不能仅凭“公共空间”名称判断。

例如：你先在“我的空间”写《安装指南》，分享给审校者后，对方从“与我分享”进入同一篇文章；确认内容后再发布到公共空间。复制是另建副本，分享则是共同访问同一份内容，两者不要混用。

### 2.2 建立目录树

在空间或目录的快捷菜单中可以创建子目录。目录支持：

- 多级嵌套；
- 重命名和删除；
- 拖拽排序；
- 移动到其他目录；
- 批量移动或批量删除；
- 导入 Markdown；
- 分享或发布到公共空间。

建议先按稳定的业务边界建立一级目录，再用二级目录区分阶段或主题。例如：

```text
产品手册
├─ 快速开始
├─ 功能说明
├─ 部署与运维
└─ 版本记录
```

**操作练习：整理第一套手册**

1. 在“我的空间”的菜单中新建“产品手册”，然后在其下创建“部署与运维”和“版本记录”。
2. 在“部署与运维”下创建《安装指南》和《备份说明》。
3. 将《安装指南》拖到《备份说明》前面，刷新后检查顺序。
4. 需要换分类时，使用移动功能选择目标目录；批量处理时先进入批量模式，再勾选目标并执行移动。

移动用于改变归属，拖拽可用于排序或改变层级，操作前看清放置位置。删除目录前检查其子目录和文章；不要把删除当作归档，也不要假设存在可恢复所有目录的回收站。

### 2.3 创建和整理文章

在目标目录的菜单中选择新建文章，填写标题后进入编辑器。文章支持重命名、移动、拖拽排序、批量移动和批量删除。

文章主页以卡片显示标题、封面、摘要、作者、字数和更新时间。你可以在当前页打开，也可以新标签页打开；需要集中整理时，可以按目录、标签、作者、文章类型或字数范围筛选。

文章类型包括笔记、博客、小说、散文和通用文章。它们主要用于标记与筛选，不会限制正文可以插入的内容。团队手册通常使用“通用文章”，个人随记可以使用“笔记”。

整理时先通过筛选缩小范围，再批量移动。例如先筛出带 `草稿` 标签的文章，确认每一项后移入“待整理”目录。批量删除之前另做备份；文章历史版本不能代替目录和账户数据的备份。

### 2.4 文章元数据

编辑器右侧的文章管理区域可以修改标题、封面、摘要和标签，同时查看作者、时间、权限和版本信息：

- 标题；
- 封面；
- 摘要；
- 标签；
- 作者、创建时间和更新时间；
- 当前权限和版本状态。

摘要可以手动填写，也可以让已配置的模型生成或润色。模型生成的内容不会直接覆盖摘要，需要先预览并明确接受。

**示例：一篇部署文章的元数据**

| 字段 | 示例 |
| --- | --- |
| 标题 | 在 Ubuntu 服务器上部署 ARTE |
| 摘要 | 介绍 Docker Compose 启动、配置调整和反向代理接入 |
| 标签 | Docker、部署、运维 |
| 封面 | 部署架构图或产品界面截图 |

填完后保存，返回文章首页，查看卡片是否能让人一眼判断“这篇文档解决什么问题”。封面负责帮助识别，摘要写适用环境与主要内容，不必把第一段正文原样复制。

## 3. 富文本、Markdown 与编辑体验

### 3.1 三种显示模式

编辑器工具栏可以在三种方式之间切换：

- **富文本模式**：直接看到最终排版，适合日常写作和内容维护。
- **Markdown 模式**：直接编辑 Markdown 源码，适合批量修改和复制已有文档。
- **左右分屏**：一侧修改 Markdown，一侧检查富文本结果，适合复杂格式转换。

**操作练习：用 Markdown 起草一段安装说明**

1. 切换到 Markdown 或左右分屏，在源码区放入下面的内容。
2. 执行“转换为富文本”，检查标题、加粗和任务列表是否按预期显示。
3. 在富文本中修改一句话，再执行“转换为 Markdown 纯文本”，检查源码结果。
4. 保存文章，重新打开确认最终内容。

```markdown
## 安装前检查

请先确认 **Docker 已启动**。

- [x] 检查磁盘空间
- [ ] 准备配置文件

入口端口由 `ARTE_PORT` 指定。
```

切换显示模式与执行转换是两件事，不要把分屏理解为任何格式都能无损实时同步。复杂单元格、字体样式、媒体播放器选项和自定义图表节点超出了标准 Markdown 的表达范围，转换前保留原文，转换后检查一次。

文章提供 Markdown 导出，本地资源还有打包处理逻辑，具体范围和检查方法见第 9 节。

### 3.2 基础排版能力

工具栏和气泡菜单支持：

- 多级标题与自动章节目录；
- 粗体、斜体、下划线、删除线和行内代码；
- 字号、字体族、文字颜色、背景色和行高；
- 左对齐、居中和右对齐；
- 有序列表、无序列表和任务列表；
- 引用、链接、分隔线、上标和下标；
- 可折叠详情区块；
- 编辑区域宽度、纸张尺寸和页面背景；
- 字数统计、正文滚动条开关，以及每篇文章 200000 字符的编辑上限。

选中文字后会出现气泡工具栏，适合快速加粗、着色或创建链接。在空行输入 `/` 会打开命令菜单，可以直接搜索要插入的内容类型。

下面这段内容本身就是编辑器能力的示例：

> 本节适用于演示环境。正式部署的配置请查看项目安装说明。

- [x] 完成目录结构
- [x] 编写快速开始
- [ ] 补充生产环境备份演练

行内代码适合标记配置项，例如 `ARTE_PORT=8000`；较长命令则应放进代码块：

```bash
docker compose ps
docker compose logs -f backend
```

**排版时如何选择**

| 内容 | 推荐形式 | 使用示例 |
| --- | --- | --- |
| 章节入口 | 标题，而不是仅放大字号 | “安装”“升级”“备份”作为二级标题 |
| 有顺序的步骤 | 有序列表 | 复制配置、修改密码、启动服务 |
| 待办事项 | 任务列表 | 发布前逐项勾选检查项 |
| 提醒和引用 | 引用块 | 标明生产环境注意事项或资料出处 |
| 不必默认展开的细节 | 可折叠详情块 | 把较长的排查过程放在“查看排查记录”下 |
| 简短参数和命令名 | 行内代码 | `ARTE_PORT`、`docker compose` |

选中文字后使用气泡菜单处理字重、链接和颜色；段落结构用标题或列表菜单设置。正文颜色少用几种，避免每段都在争夺注意力。字号、宽度、纸张背景等是阅读与编辑展示设置，不能据此承诺导出 PDF 或打印分页效果。

### 3.3 斜杠命令

在空段落输入 `/` 后，可以插入：

- 普通文本和一至三级标题；
- 项目列表、编号列表和任务列表；
- 分隔线、引用、表格和代码块；
- Mermaid、Draw.io、思维导图和自由画布入口；
- 图片、音频和视频；
- AI 写作块。

命令支持继续输入关键词过滤。例如输入 `/mer` 可以快速定位 Mermaid，输入 `/AI` 可以找到 AI 写作。选择后，普通段落会直接变为相应类型，媒体和图表通常会继续打开输入窗口。

试着在新空行输入 `/`，选择任务列表，写入“检查图片链接”，再按回车添加第二项。需要插入代码时，另起空行重新调用菜单，避免在现有段落中误改结构。自由画布目前只有入口，不作为已完成的可用功能，详见文末边界说明。

### 3.4 键盘快捷操作

编辑器在 TipTap 默认快捷键之外增加了几组面向文档维护的操作：

| 快捷键 | 作用 |
| --- | --- |
| `Ctrl/Cmd + S` | 保存当前文章 |
| `Ctrl/Cmd + K` | 为选中文本插入或编辑链接 |
| `Ctrl/Cmd + Shift + F` | 格式化当前选区 |
| `Ctrl/Cmd + Alt + Shift + T` | 插入 3×3 表格 |
| 表格内 `Ctrl/Cmd + Shift + Enter` | 在当前行上方插入一行 |
| 表格内 `Ctrl/Cmd + Enter` | 在当前行下方插入一行 |
| 表格内 `Ctrl/Cmd + Backspace` | 删除当前行 |

Windows 和 Linux 使用 `Ctrl`，macOS 使用 `Cmd`。浏览器或系统快捷键可能与组合键冲突，首次使用时应在非关键文档中确认。

### 3.5 查找、替换与章节定位

正文搜索支持上一处、下一处、区分大小写和正则表达式。编辑模式下还可以替换当前匹配或全部替换。

**示例：统一旧称**

1. 打开正文的查找/替换工具，查找 `测试环境`。
2. 用上一处、下一处逐个查看命中位置，确认没有误改引用或代码的风险。
3. 填写替换词 `演示环境`，先替换一处检查效果，再决定是否全部替换。
4. 保存后再搜旧词，确认剩余匹配符合预期。

正则适合更有规律的修改，例如查找 `v[0-9]+\.[0-9]+` 定位版本号。先在测试文章确认匹配范围，尤其不要不加检查地批量改写命令参数。正文查找只在当前文章内工作，跨文章检索使用第 7 节的文章搜索。

章节标题会同步到右侧章节列表。点击章节可以定位正文；URL Hash 可以携带章节位置，用于分享某个具体段落。刷新页面时，系统会优先恢复 URL 指定的章节或上次阅读位置。

### 3.6 保存状态与阅读位置

编辑器底部会显示“未变化”“未保存”“保存中”“保存成功”或“保存失败”等状态，并同时显示最后修改人、修改时间和字数。离开长文档前，不要只依赖按钮点击，应确认状态已经回到“保存成功”或“未变化”。

当前编辑器每 60 秒检查一次是否需要自动保存，只有处于可编辑状态且存在未保存修改时才提交。重要操作后仍可按 `Ctrl/Cmd + S` 主动保存；自动保存不是断网备份，出现失败时先复制尚未保存的内容，再排查网络或权限。

ARTE 在当前浏览器会话中记录文章的光标和滚动位置。再次打开同一文章时恢复位置；URL 中的章节 Hash 优先于上次位置。这是会话内的位置记录，不是跨设备同步书签。

试着打开长文中的某个章节，复制包含章节定位信息的链接，再在另一个页面打开。接收者仍需拥有文章访问权限，定位链接本身不会授予权限。

### 3.7 粘贴、拖放与格式清理

从网页或办公文档粘贴文字时，可以选择是否保留字号、字体、颜色、背景、粗体、斜体和下划线等样式。对于团队手册，建议只保留必要格式，避免正文出现大量不一致的内联样式。

拖入或粘贴图片时，编辑器会自动上传图片；其他文件会上传后作为可下载链接插入。粘贴较长代码时，编辑器会尽量把它识别成独立代码块。

编辑器也包含 `@` 提及节点，但当前候选列表仍是前端示例数据，尚未接入“拥有当前文章权限的真实成员”查询。它可以用于验证格式，不应作为已经完成的团队通知能力宣传。

## 4. 表格、代码、公式与图表

选择图表时，先看你希望怎样维护它：Mermaid 适合文字定义的流程；Draw.io 适合精细布局与架构图；思维导图适合发散整理主题。它们不需要都出现在一篇文档里。

### 4.1 表格

通过工具栏的表格入口选择行列数，或输入 `/表格` 直接插入默认表格。选中单元格时可以：

- 新增、删除和移动行列；
- 设置表头；
- 合并或拆分单元格；
- 调整列宽；
- 设置单元格垂直对齐；
- 删除整张表格。

表格适合配置对照、版本兼容矩阵和参数说明。简单表格可以转换为 Markdown；合并单元格、列宽和垂直对齐等不能指望由标准 Markdown 完整保留。

**示例：服务说明表（演示数据，不是运行检测结果）**

| 服务 | 端口 | 用途 | 备注 |
| --- | ---: | --- | --- |
| frontend | 8000 | 网页入口 | 此处为主机映射端口 |
| backend | 12636 | 业务接口 | 此处为容器内部端口 |
| elasticsearch | 9200 | 搜索服务 | 此处为容器内部端口 |

**操作练习**

从工具栏插入四列四行的表格，按上例填写表头与内容；把光标放进最后一行，按 `Ctrl/Cmd + Enter` 新增一行，填写 `drawio / 8080 / 图表编辑 / 容器内部端口`。拖动列边界，给“备注”留出更大宽度。合并单元格练习请另建测试表，选中相邻单元格后从表格菜单合并，再尝试拆分。

### 4.2 代码块

### 4.3 数学公式

## 5. 图片、音频、视频与附件

媒体适合解释文字不容易说清的操作。图片展示某一步的状态，GIF 展示短动作，视频展示较长过程，音频则保留声音。先准备自己有权使用的测试文件，不要直接拿内部会议或客户资料做公开演示。

### 5.1 图片

图片可以从本地上传，也可以通过 HTTP/HTTPS 地址插入。选中图片后可以设置 Alt、标题、宽度和高度，并拖动四角按比例缩放。

使用建议：

1. 上传后先填写描述性的 Alt，方便无障碍阅读和资源失效时识别内容。
2. 截图只保留与当前步骤有关的区域，避免泄露无关信息。
3. 把适合列表展示的图片设为文章封面。
4. 点击图片进入预览，可缩放、前后切换、复制图片或定位回正文。

**操作练习：给安装步骤配图**

在“修改配置”段落后另起一行，输入 `/图片`，上传一张已隐藏敏感字段的截图；将 Alt 写为“ARTE 配置文件中的监听地址与入口端口”，调整宽度后保存。进入阅读模式点击图片，检查放大后文字可读、返回正文的位置正确。

GIF 可作为图片素材尝试上传，但需要在实际实例检查上传后是否仍保留动画。对于 HTTP 图片，系统会尝试转存，以减少混合内容问题；长期资料更适合上传到自己控制的存储。

视频支持 MP4、WebM、HLS、DASH、YouTube、Vimeo 和 Bilibili 等来源。可以设置：

PDF、Word、Excel、PowerPoint、ZIP、文本和 CSV 等文件可以拖放或粘贴上传，并以附件链接插入正文。

**示例：附上验收清单**


## 6. AI 模型、助手与写作工具

先区分三个概念：**模型**决定请求发给哪家服务、用哪个模型；**助手**保存用途、提示词和上下文等配置；**会话**记录一次具体讨论。编辑器中的续写、翻译、摘要和文章问答，是写作时调用 AI 的不同入口。

本文中的提示词是演示输入，不是模型回答。接入外部服务时，所选文字、上下文或知识库片段会发送到该服务，可能产生费用。请先确认数据使用范围；本地部署 ARTE 并不会自动把外部模型变成本地模型。

### 6.1 先配置模型

进入“AI 助手 → 模型”，新建模型配置。常用字段包括：

- 配置名称；
- 提供商；
- 模型 ID；
- API Base URL；
- API Key；
- 上下文窗口、最大 Token 与默认参数 JSON。

填写后使用模型列表提供的连通性测试，确认配置可用，再决定是否启用、置顶或设为默认模型。API Key 不应出现在截图、文章或 Git 提交中；回到配置页时也应确认敏感值没有被公开展示。

| 字段 | 怎么填 | 容易混淆的地方 |
| --- | --- | --- |
| 配置名称 | 如“文档审校模型” | 这是便于自己识别的名称，不是接口模型 ID |
| 提供商 | 与所用接口适配路线匹配 | 同样叫“兼容接口”，也可能存在功能差异 |
| 模型 ID | 服务方实际提供且账户可用的标识 | 不要直接照抄别人的模型名 |
| Base URL | 服务方要求的接口基础地址 | 不是产品首页，也不要无依据地追加完整请求路径 |
| API Key | 使用你授权给此实例的密钥 | 建议限制用途与额度，演示时不录入镜头 |
| 上下文窗口、输出上限、默认参数 JSON | 按模型能力填写，扩展参数只添加明确支持的项 | 实际生效范围取决于适配器和服务端 |

建议先建立一个低风险的测试配置，用一小段公开文字验证对话、摘要和翻译。确认模型 ID、地址、权限和计费均符合预期后，再让它处理内部文章。不要用尚未验证的模型配置直接批量改写重要文档。

当前实际启用的适配路线以兼容 OpenAI 的接口和 DeepSeek 为主。代码中出现的其他提供商枚举或草稿，不代表已经完整适配。

模型还可以描述视觉理解、函数调用、深度思考、联网搜索和提示缓存等能力，界面据此展示相关选项。勾选能力标记不会让模型自动获得这些能力，应按服务方实际支持情况填写。

进阶配置还包括代理、超时、重试次数、输入/输出单价和币种。网络不稳定时先核对代理与超时，再决定是否增加重试；重试仍可能产生请求费用。输入与输出单价用于结合返回的 Token 数估算费用，以服务商实际账单为准。

表单还列有每分钟请求数、每日请求数和并发限制等字段。当前不能仅凭这些字段就认定已实现完整的限流或费用封顶；需要限制真实开销时，同时在模型服务端设置额度。

> **[待补素材 F12｜模型连接测试｜PNG]**
> 在已授权的模型配置上执行测试，截取配置名称、模型 ID 和实际测试结果。不要展示完整 API Key、私有网关地址或计费信息；没有可用配置时保留占位，不制作“连接成功”示意图。
> 文件：`assets/captures/f12-model-test.png`。图注：*使用前先确认模型配置能够完成实际请求。*

### 6.2 建立一个 AI 助手

助手把模型、系统提示词、知识库和上下文策略组合在一起：

1. 新建助手并选择模型。
2. 填写助手名称和系统提示词。
3. 如需文档检索，在知识库类型中选择文章知识库。
4. 设置上下文策略并启用助手。
5. 如有需要，把它设为默认助手。

**示例系统提示词**

```text
你是项目运维手册助手。优先依据知识库回答；如果资料中没有明确结论，
请指出缺少的信息，不要推测密码、端口或生产环境状态。
```

可把这个助手命名为“运维手册助手”，然后新建会话提问：“升级前需要备份哪些数据？按本文已有信息列出，不要补写命令。”用下面第 6.7 节的测试资料检查回答是否有据可依。

助手支持新建、编辑、置顶、启用和禁用。会话支持新建、编辑、置顶和归档：把日常使用的助手置顶，把同一问题留在同一会话，换到另一项工作时新建会话，避免旧上下文混入。

上下文策略决定携带哪些历史内容及其范围。连续讨论适合保留必要历史，独立问题可另开会话；不是携带越多内容，回答就一定越准确。助手配置中的知识库选项是类型选择，不等于已经创建了一套独立的资料空间；也不要把系统提示词当成文章权限或严格的目录筛选条件。

### 6.3 对话能力

对话页面以流式方式接收模型输出，并支持：

- 停止生成；
- 重新生成；
- 编辑消息后重发；
- 引用历史消息；
- 查看模型思考内容；
- 查看 Token 用量；
- 使用文章知识库作为 RAG 上下文。

**示例：修正一个提问，而不是不断补充解释**

先问“帮我检查安装说明”，如果范围太宽，编辑消息为“只检查安装说明中命令与端口是否前后一致，逐项指出原句，不要重写全文”，再发送。结果偏题时可以停止生成；仅想换一种回答时再重新生成。

引用某条历史消息适合围绕其中一句继续追问。思考内容、Token 信息等只有在所用模型和接口返回相应数据时才有意义，不能把缺少显示认定为请求失败；也不应把推理文本当作事实证据。

### 6.4 编辑器中的 AI 补全

AI 补全会读取光标附近和当前章节的上下文，生成续写建议。它适合补全定义、步骤或过渡段，不适合代替事实核对。

例如正文中已经写下：

```text
生产环境升级前，应先完成数据库、索引和上传文件的备份，然后……
```

先在编辑器中选择可用模型，再把光标放到普通段落末尾，输入 `//` 触发补全。出现建议后按 `Tab` 或 `Enter` 接受，按 `Esc` 取消。该触发不会在代码块内按同样方式工作，也会避开 URL 中的 `://`。

例如在上面这段话后输入 `//`，观察建议，再决定采用或取消。补全读取附近文字及章节上下文；它不知道真实服务器是否备份成功，不要把推测写成已完成操作。

> **[待补素材 F13｜AI 补全｜GIF，12～20 秒]**
> 使用公开测试文字，录制输入 `//`、出现建议、按 `Tab` 接受；另录一次 `Esc` 取消可作为补充。保留真实生成结果，较长等待可剪去，但不要暗示所有模型都能瞬时响应。
> 文件：`assets/captures/f13-ai-completion.gif`。图注：*先看续写建议，再选择接受或取消。*

### 6.5 AI 写作块

在空行输入 `/AI 写作`，填写自定义提示词后生成内容。生成结果先显示在写作块中，确认后再插入正文。

例如，要补一段安装说明，可以写：

```text
根据本节已有内容，补充一段面向首次部署者的说明：
解释为什么不能把 MySQL、Redis 和 Elasticsearch 直接暴露到公网；
控制在 120 字以内，不要添加本文没有出现的端口。
```

生成完成后先核对事实，再使用写作块的插入操作放入正文。若要求没有满足，调整提示词重新生成；提交请求本身不等于你已采用结果。AI 写作块适合明确说明任务，补全则适合顺着现有文字继续写。

### 6.6 翻译

选中正文或把光标放在目标段落，打开翻译工具，选择目标语言。翻译结果可以：

- 替换原文；
- 插入到原文后；
- 作为引用插入。

**操作练习**

选中“升级前请备份数据库和上传文件。”，打开翻译工具，选择英语。先使用“插入到原文后”，保留中文用于对照。检查结果是否同时提到 database 和 uploaded files，再决定是否用于双语手册。

翻译请求会携带前后的有限上下文，以减少术语误译。API 名称、命令、占位符和配置项应保留原有拼写；“替换原文”会改变正文，用之前先确认选区没有多选其他段落。

> **[待补素材 F14｜选区翻译｜GIF，12～18 秒]**
> 录制选中示例句、打开翻译、查看真实结果、插入原文后。末帧保留双语对照；不要预填一段人工译文冒充生成结果。
> 文件：`assets/captures/f14-translation.gif`。图注：*翻译结果可先放在原文后，检查后再决定如何采用。*

### 6.7 摘要与文章问答

“文章摘要”可以基于正文生成摘要，也可以润色已有摘要。只有接受并保存后，结果才会成为文章元数据。

“文章问答”围绕当前文章建立对话，适合读长文时提取步骤、解释术语或核对遗漏。当前单篇文章路径直接读取文章内容，多文章检索路径则使用索引中的相关片段，两者并不都是“先搜索整套知识库”。AI 回答可回填到当前光标位置，回填之前核对内容。

**可复现的测试资料**

把下面内容保存为《演示项目备份约定》，所有数值都只是教程设定：

```text
演示项目备份约定

升级前备份 MySQL 与上传文件，备份副本保留 7 天。
恢复检查必须包含：打开一篇文章、显示一张图片、下载一个附件。
本约定尚未确定异地备份位置。
```

打开这篇文章的问答入口，可以依次试问：

| 提问 | 检查重点，不是预制模型输出 |
| --- | --- |
| 升级前要备份什么？ | 是否准确包含 MySQL 和上传文件 |
| 恢复后检查哪三项？ | 是否包含文章、图片、附件 |
| 异地备份放在哪台服务器？ | 是否说明原文未确定，而不是虚构主机地址 |
| 给这篇文章写一句摘要 | 是否概括范围，不擅自扩大为完整生产备份方案 |

同一份资料也可用于知识库助手测试。如果回答遗漏了内容，先检查选用的是当前文章问答还是跨文章检索，以及原文是否保存、索引是否可用。

> **[待补素材 F15｜文章问答与摘要｜两张 PNG]**
> 第一张展示备份约定原文和“恢复后检查哪三项”的真实回答；第二张展示摘要生成后的预览与采用入口。使用测试资料，不显示真实内部文档。

## 7. 搜索、索引与知识库

### 7.1 结构化筛选

在文章首页搜索框输入关键词，按回车或点击搜索。展开更多条件后，可以结合作者、标签、目录、文章类型和字数范围筛选，也可勾选“搜索标题”限定标题查找。目录选择器按空间分组；选中一个目录时，不应默认认为所有未选中的子目录都已纳入。

**示例：找到部署类说明**

1. 先用 `备份` 搜索，观察文章标题和摘要。
2. 展开条件，选择目标目录或 `运维` 标签，再次搜索。
3. 如果只想找标题叫《备份说明》的文章，勾选“搜索标题”；如果要找正文里的备份段落，则不要只搜标题。
4. 结果过少时逐项清除筛选条件，判断是关键词问题还是范围过窄。

搜索条件是在缩小或调整结果范围，不会自动修改文章的标签和归属。

### 7.2 全文、向量与混合检索

文章保存后，后端会把内容拆分成文档和内容块，并异步同步到 Elasticsearch。检索层支持：

- 标题、正文、作者和标签过滤；
- 基于关键词的全文相关性；
- BGE 中文嵌入模型驱动的向量检索；
- 关键词和向量结合的混合检索；
- 当前用户权限过滤；
- 为 AI 对话提供相关片段。

界面中的“相关性搜索”对应语义检索选项。记得命令或原词时先用关键词；只记得大意时，再开启相关性搜索，用自然语言描述问题。

**对照练习**：将第 6.7 节的示例文章保存后，先搜索 `上传文件`，再开启“相关性搜索”搜索 `恢复后怎么确认资料完整`。比较返回内容是否与原文的三项恢复检查有关。这里的目标是观察语义相近的检索效果，不保证某条结果固定排在第一位。

> **[待补素材 F16｜筛选与相关性搜索｜GIF，15～25 秒]**
> 先搜索确切词“上传文件”，展开条件，再演示开启“相关性搜索”后的自然语言查询。录入实际结果，不修改排名或拼接不存在的命中。
> 文件：`assets/captures/f16-search.gif`。图注：*记得原词时搜关键词，只记得大意时试试相关性搜索。*

### 7.3 嵌入模型与索引维护

部署配置可以选择 BGE Small 或 BGE Large。Compose 默认采用更适合单机启动的 BGE Small 路线。更换嵌入模型后，旧向量不再处于同一语义空间，应重建对应索引。

文章删除时，业务数据、文章索引和内容块索引需要保持同步。若搜索结果短时间内仍出现刚修改的内容，应先确认异步索引任务和 Elasticsearch 服务状态。

检索结果还要结合文章、目录与祖先目录计算有效权限。测试时至少准备一个有权账户和一个无权账户，分别检查搜索及问答结果，不能只看管理员的结果就认定权限隔离已验证。

全文与向量索引主要来源于文章可提取的文字。插入图片、音频或附件不代表自动完成 OCR、语音转写或附件全文解析。如果要检索图片中的关键结论，请在正文中补上文字说明。

## 8. 分享、权限、批注与版本

### 8.1 分享给用户或角色

目录和文章都可以分享给具体用户或角色：

1. 打开目标内容的“分享设置”。
2. 选择用户或角色。
3. 设置允许的操作。
4. 保存后，在分享列表中复核授权。

分享者可以查看和取消已有授权；接收者可以在“与我分享”中访问，也可以离开某项分享或复制到自己的空间。

**示例：把《安装指南》交给同事审校**

选择一个此前没有该目录编辑权限的测试成员，仅授予阅读和批注所需权限。对方登录后，从“与我分享”打开文章，尝试添加批注并确认不能修改正文。完成后取消授权，再由对方重新打开检查访问结果。

如果该成员还通过角色或上级目录获得编辑权限，给单篇文章追加“批注”授权不一定能把既有编辑权限降下来。测试授权时必须同时检查这些来源。

### 8.2 权限如何生效

系统会结合文章、所在目录和祖先目录计算有效权限，覆盖读取、批注、编辑、删除、授权和创建子内容等动作。

前端据此提供三种模式：

- **阅读模式**：只查看内容。
- **修订模式**：阅读并添加批注，不直接改写正文。
- **编辑模式**：修改正文和元数据。

“修订模式”在这里指批注审校，不是 Word 式逐字跟踪修订，也不意味着正文里的每项修改都有接受/拒绝按钮。

| 角色示例 | 需要的能力 | 核对方式 |
| --- | --- | --- |
| 读者 | 阅读 | 能打开文章，不能直接改正文 |
| 审校者 | 阅读、批注 | 可以讨论原文，不拥有不必要的编辑能力 |
| 维护者 | 编辑，按需管理内容 | 可以保存修改；是否能删除或再授权要单独确认 |

角色名称只是教程示例，实际权限按系统中的动作设置。菜单权限决定是否可以使用某项管理功能，内容权限决定可以访问哪篇文章，两者不能相互替代。

### 8.3 批注线程

选中一段正文后，可以创建批注。批注支持：

- 回复；
- 编辑和删除单条回复；
- 解决和重新打开；
- 删除整个线程；
- 从侧栏定位回正文高亮。

**示例批注**

```text
这里的 7 天是演示约定，还是实际生产备份策略？
请标明适用范围，避免读者直接照搬。
```

**完整审校过程**

选中示例文章中的“备份副本保留 7 天”，添加上面的批注；由维护者回复“这里是教程约定，不是生产策略”，再把正文补充清楚。确认后将线程设为已解决。如果后来发现仍有遗漏，可以重新打开线程继续讨论。

点击侧栏线程检查是否能定位到对应高亮。批注用于保存讨论，解决不等于已经修改正文，也不应把最终结论只藏在回复里。

> **[待补素材 F17｜批注处理｜GIF，18～25 秒]**
> 用两个测试账户录制选区批注、回复、修改正文、解决线程；可分别录两个账户的画面，但明确标注切换，不伪装成同屏实时编辑。
> 文件：`assets/captures/f17-comments.gif`。图注：*从指出问题，到修改原文，再结束这次讨论。*

### 8.4 历史版本与差异对比

后端会保存文章历史版本。右侧“版本”面板列出版本号、修改人和时间；进入对比视图后，可以分别选择左右两侧的历史版本或当前内容，并通过上一处、下一处差异按钮定位改动。

**操作练习：找出一处约定变化**

1. 保存“演示备份副本保留 7 天”，等待保存成功。
2. 把 `7 天` 改为 `14 天`，再次保存；再补一句“仅用于功能演示”并保存，让列表中有多次修改可比较。
3. 打开右侧“版本”，进入对比视图，一侧选择包含 `7 天` 的旧版本，另一侧选择当前内容。
4. 用差异定位按钮查看数字改动，再把一侧切换为包含 `14 天` 的历史版本，观察新增说明句的差异。

这个例子中的保留天数只是便于观察差异。找回旧段落时，从历史内容中取回需要的文字，再保存到当前文章。当前介绍的是版本查看与对比，不提供整库回滚。编辑器的撤销处理编辑操作，与服务器上的版本记录不同。

> **[待补素材 F18｜历史差异｜GIF，12～18 秒]**
> 录制上述数字改动后的历史对比，再切换一次版本。画面中保留版本时间和实际差异，确保文字清晰。
> 文件：`assets/captures/f18-history.gif`。图注：*对照历史内容，确认这次修改改了什么。*

### 8.5 并发编辑提醒

文章使用版本号进行并发控制，并通过 WebSocket 推送版本变化。当其他用户更新同一篇文章时，当前页面会提示刷新或忽略，降低旧页面覆盖新内容的风险。

看到提醒时，先把本地尚未保存的改动复制到临时文本，比较新版本后再合并保存。不要为“先保住自己的内容”直接再次覆盖远端。

可以用两个浏览器会话打开同一测试文章：A 保存一处修改，观察 B 的版本提醒；B 刷新前保留自己的未保存文字。ARTE 当前的协作方式是权限、批注、版本和冲突提醒，不是多人光标同步的实时协同编辑。

## 9. 导入、导出、发布与迁移

### 9.1 导入单篇 Markdown

在目标目录菜单中选择“导入 Markdown 文章”，选择 UTF-8 编码的 `.md` 文件。文件名用于生成文章标题，导入后核对是否需要调整。

可以把第 3.1 节的示例保存为 `安装前检查.md`，导入到测试目录，检查二级标题、加粗、任务列表和行内代码。单独导入 `.md` 不会自动读取你电脑上的其他文件；正文有相对图片路径时，把图片一起放进 ZIP 再按下一节导入。

### 9.2 导入 Markdown ZIP

压缩包可以包含多篇 Markdown。系统会读取 Markdown 文件，并识别压缩包中的相对图片路径，把图片上传后替换正文引用。

推荐结构：

```text
handbook.zip
├─ README.md
├─ deploy.md
└─ assets
   ├─ overview.png
   └─ topology.png
```

在 `README.md` 中这样引用图片，注意路径相对于该 Markdown 文件所在位置：

```markdown
# 产品手册

![工作区概览](assets/overview.png)
```

把上面这些文件与 `assets` 目录放入同一个 ZIP，在目标目录选择 ZIP 导入。完成后打开导入的文章，确认图片已经显示，再保存和刷新检查一次。

文件夹结构有助于解析资源路径，但不要因此假设 ZIP 会原样还原 ARTE 的目录树、权限、标签和版本历史。此路径重点处理 Markdown 与相对图片引用，不等于支持音视频、任意附件和自定义节点的完整迁移。

> **[待补素材 F19｜带图 Markdown 导入｜GIF，15～20 秒]**
> 先展示 `README.md` 与 `assets/overview.png` 的文件结构，随后录制选择 ZIP、导入完成、打开文章看到图片。使用自己制作的截图，不上传无关文件。
> 文件：`assets/captures/f19-import.gif`。图注：*把 Markdown 和相对路径图片一起导入。*

### 9.3 批量导出

单篇文章可从编辑器菜单导出 Markdown；目录中的文章导出会将所选文章按标题分段、用分隔线连接，汇总为一个 Markdown 文件。它用于带走正文，不保留整棵目录树与授权关系。

导出工具包含识别本地富文本资源、下载并打包到 ZIP 的逻辑，但不是所有外链、HTML 媒体和图表源文件都能自动带走。当前资源收集仍有完整性风险，尤其要检查正文第一处资源链接；正式迁移不要仅依赖导出包。

**导出后如何检查**：用本地预览器打开 Markdown，逐张确认图片，逐个打开附件链接；检查第一个资源是否存在、是否仍引用旧站点地址、图表是否只剩预览。再在测试目录导入一份，确认文字和图片。需要完整恢复时，使用数据库与上传文件备份，而不是只保留 Markdown。

### 9.4 公共空间发布与撤回

私有空间的目录或文章可以选择目标公共目录后发布。已经发布的内容可以撤回；共享或公共内容也可以复制到个人空间形成独立副本。

操作时，从原目录或文章菜单进入发布，选择目标公共目录并确认；切换到公共空间找到发布结果，使用目标读者的身份打开。撤回后再次检查公共入口和旧链接的表现。不要把发布理解为创建一个与你的后续修改永久隔离的快照。

> **[待补素材 F20｜发布与读者视图｜两张 PNG]**
> 第一张展示目标公共目录选择；第二张展示普通读者打开后的正文。用不含内部资料的测试文章，发布前确认确实允许公开。
> 文件：`assets/captures/f20-publish.png`、`assets/captures/f20-reader.png`。图注：*选择发布位置后，再以读者身份检查结果。*

发布前建议完成四项检查：

- 正文是否包含内部地址、密钥或个人信息；
- 图片是否暴露了无关界面；
- 链接是否对目标读者可访问；
- 当前读者是否需要登录或额外权限。

完成发布后，最好再使用无管理权限的账户复核一次，并在窄屏下查看长表格、代码块和媒体是否被截断。公开页面能打开，不等于正文内的附件和链接也具备相同访问权限。

## 10. 个人工具

### 10.1 标签管理

标签支持树形结构、创建、编辑、删除和排序。文章可以关联多个标签，用于跨目录聚合内容。

进入标签管理，先建“技术”父标签，再建 `Docker`、`Elasticsearch` 等子标签；回到文章元数据，将需要的标签关联到文章，再从搜索条件选择标签查找。

目录表达“内容属于哪里”，标签表达“内容涉及什么”。例如文章位于“部署与运维”，同时拥有 `Docker` 和 `备份` 标签。重命名或删除共享使用的标签前，先确认哪些文章会受影响；不要把删标签当作删文章。

### 10.2 便笺

在便笺页面新建一张便笺，写下“补录安装视频”；再建一张“核对文档中的旧端口”。拖动位置区分优先级，调整大小方便阅读，用不同主题色区分待办与资料，暂时不用的便笺可以折叠。

便笺支持创建、移动、缩放、折叠、排序和主题色切换，适合短期记录。这不是自动到期通知或项目任务系统；完成整理后，把需要长期维护的结论放进正式文章。

### 10.3 文本格式化

进入文本格式化工具，将待整理文字放入输入区域，按需要选择列表、空格、标点或 Markdown 表格处理，再查看输出。

例如，将两行“检查磁盘空间”“准备配置文件”放入输入区域，启用列表处理并选择数字序号，检查输出是否按行编号。需要整理 Markdown 表格时切换到表格处理；列表与表格面板互斥，不是同时套用两套规则。

工具还可配置获取焦点时处理剪贴板、将结果写回剪贴板。首次使用建议先关闭自动写回，手动检查结果再复制；处理命令、URL 或代码时，特别留意空格和标点。

### 10.4 外观与语言

通过界面的主题与语言入口切换明暗外观和界面语言。编辑长文时，还可以按需要调整正文区域宽度与背景，让代码、表格和连续段落更易阅读。

切换后检查同一篇文章在两种主题下的文字颜色与图片对比度，尤其是手动设置了背景色的段落。界面语言切换不会翻译文章，文章翻译使用第 6.6 节的工具。

### 10.6 首页资讯

例如，进入实例已配置的一个分类，先看某个网站卡片上的标题与摘要，再悬停查看其余条目，选择感兴趣的一条打开。资料适合留作笔记时，把自己的摘录、理解与原始链接整理进文章；首页浏览不会自动为每条资讯创建知识库文章。

内容依赖服务端的数据源配置、抓取规则与外站可达性。当前不应将它介绍为已提供普通用户自助添加任意 RSS 源的订阅器，也不保证外部网站更新后立即同步。

## 11. 用户、角色与菜单管理

系统管理覆盖：

- 用户创建、编辑、停用和状态维护；
- 角色创建、编辑、停用和用户分配；
- 菜单与菜单操作管理；
- 向用户或角色授予菜单和操作权限；
- 基于 JWT 的登录认证；
- 使用 SM2 保护登录密码和模型密钥等敏感字段的传输。

这些功能由拥有相应管理权限的账户使用，不是每个写作者都能看到。

**示例：配置一位文档维护者**

1. 在角色管理中建立“文档维护者”角色，填写说明并启用。
2. 为角色分配所需菜单和操作，不要为了方便直接开放全部系统管理。
3. 在用户管理中创建测试用户，将该角色分配给用户。
4. 单独把“产品手册”目录授予该用户或角色适当的内容权限。
5. 使用测试用户登录，分别检查菜单可见性、文章读取与编辑能力；再检查其不应看到或操作的内容。

用户与角色可以维护状态、分配关系；菜单管理维护入口结构，菜单操作管理维护具体操作授权。给用户授予菜单，并不会自动给他所有文章的编辑权；分享一篇文章，也不代表允许他管理其他用户。

停用用户前检查其内容归属和长期分享关系。JWT 登录认证与 SM2 敏感字段传输处理不是端到端文档加密，也不能替代 HTTPS。首个管理员的新装问题见[部署说明](120-如何开始.md#start-account)。

## 12. 私有部署、存储与扩展

### 12.1 Docker Compose 服务

标准部署包含 frontend、backend、MySQL、Redis、Elasticsearch 和 Draw.io，Kibana 为可选观测组件。前端是统一访问入口，数据库、缓存和搜索服务不应直接暴露公网。

详细安装、配置、升级与备份步骤请阅读[部署指南](120-如何开始.md)。

### 12.2 文件存储

上传文件可以使用两种存储后端：

- `LOCAL`：写入本机目录，Docker 部署映射到持久卷。
- `QINIU`：写入七牛云对象存储。

更换存储 Provider 不会自动迁移已有文件。切换前需要规划旧资源复制、URL 兼容和备份恢复。

本地存储无需在写作界面设置，Compose 已为后端挂载上传目录。上传测试图片、保存文章、重新打开后确认图片仍可读，是最直接的检查方式。

使用七牛云时，由部署者配置存储空间、访问域名、Access Key 和 Secret Key，再切换后端存储类型。标准 Compose 把 `RICH_TEXT_STORAGE_TYPE` 明确设为 `LOCAL`，仅在 `.env` 追加一个同名变量不会自动覆盖它，还要调整后端容器的环境配置。先在测试实例验证图片、附件及图表源文件，再迁移正式资料；存储密钥不要填写进文章正文。

### 12.3 MCP

后端包含 MCP Client 与 MCP Server 支持，并提供工具、资源、参数补全和翻译 Prompt 的示例。默认端点位于应用上下文下的 `/mcp`，可作为继续扩展 ARTE 与 MCP 客户端集成的入口。

当前仓库中的 MCP Tool 仍以示例性质为主，不应把它理解为已经开放了完整的文章和知识库 API。开发者可从工具与资源的示例实现继续接入自己的客户端；在暴露端点之前单独确认鉴权、可执行动作和网络范围。

## 13. 三种常见落地方式

### 13.1 个人研究资料库

- 用目录区分项目或主题。
- 用标签关联跨主题概念。
- 把网页摘录、PDF 和图片放进文章。
- 使用语义搜索找回表达不同但含义相近的资料。
- 定期导出 Markdown 并备份附件卷。

### 13.2 团队产品手册

- 在公共空间建立稳定目录结构。
- 维护者使用编辑权限，其他成员使用修订权限。
- 通过批注完成审校，解决后把结论写回正文。
- 用历史版本记录重要变化。
- 为安装、升级和故障排查提供可复制的命令示例。

### 13.3 带知识库的 AI 助手

- 先整理高质量文章，而不是直接导入杂乱资料。
- 配置并测试模型。
- 为助手选择文章知识库类型和明确的系统提示词。
- 用权限限制可检索文章范围。
- 对回答中的命令、版本和安全结论进行人工复核。

## 14. 用一篇文章体验核心功能

不必一次配置所有功能。准备一篇不含敏感信息的测试文章，按下面的顺序操作，就能覆盖 ARTE 最核心的使用链路：

1. 在“我的空间”创建“体验 ARTE”目录和一篇通用文章。
2. 写入两级标题、一段引用、一份任务列表和一个三列表格。
3. 输入 `/`，分别插入代码块、Mermaid 图表和一张测试图片。
4. 保存后刷新页面，确认正文、图表和图片仍然完整，保存状态回到“未变化”。
5. 修改一小段正文并再次保存，在“版本”中对比两次内容。
6. 为一句话添加批注并回复，确认可以从侧栏定位回原文。
7. 给文章添加封面、摘要和标签，然后回到文章首页用标签找到它。
8. 如果 Elasticsearch 正常，使用正文中的一句话搜索；如果已经配置模型，再尝试摘要或文章问答。

团队环境还应把文章以“阅读”或“批注”权限分享给测试成员，使用对方账户确认能看到的内容和可执行的操作与授权一致。完成这些步骤后，再决定是否导入正式资料、配置公共空间和接入生产模型。

做完后，你应该得到一篇带目录层级、任务、表格、代码、流程图与图片的文章，以及一条批注和可查看的历史差异。随后再导出并检查资源，就能判断这套写作方式是否适合现有资料。

## 15. 当前边界

下面这些区别会影响选型与使用，请在正式导入资料前确认：

- 自由画布入口已经预留，但仍等待后续 Provider 接入。
- 更多模型提供商虽然存在枚举或适配器草稿，实际可用性应以启用的适配器和连通性测试为准。
- AI 图表生成仍属于实验能力，正式文档优先使用人工创建和编辑的 Mermaid、Draw.io 或思维导图。
- 多人协作以权限、批注、版本和并发提醒为主，不是实时多人光标同步，也不是逐字建议修订。
- Markdown 导出不等于数据库备份；当前资源收集存在遗漏风险，图片、附件、图表源文件均应检查。
- 媒体嵌入不等于 OCR、语音转写或附件全文检索；模型能力标记不等于已完成对应模型适配。
- 首次用于重要环境前，应在真实部署上完成安装、升级、权限与备份恢复检查。
- `@` 提及当前仍使用示例候选人，没有连接真实用户和通知流程。
- 账户设置和仪表盘等页面包含模板或占位功能；首页资讯依赖已有数据源配置，不能等同于完整订阅服务。
- 全新数据库没有内置管理员数据，现有注册页面也没有对应的后端注册实现；首次账户初始化是当前 Docker 新装流程的阻塞项。
