# 新聊天第二步：最小聊天闭环

本文记录第二步范围；当前页面已继续完成 [第三步执行控制与异常处理](ai-new-chat-step3.md)。

入口继续使用 `/AI/Chat`。在第一步会话管理基础上，接入文本输入、明确外发确认、耐久历史、执行状态查询、完整回答与继续追问。 沿用现有
ai-new 会话／模型服务、base 授权与执行契约及新表，本次没有新增表、迁移旧聊天或更换默认模型。

## 使用流程

1. 按 [第一步接入说明](ai-new-chat-step1.md) 完成登录、菜单、表与服务配置。真实生成还需要当前
   AI／外发许可、受控连接、用途规则、同意、预算额度及可解析的凭据引用。
2. 选择或创建会话，输入文本。页面按 UTF-8 字节验证当前问题不超过服务端提供的上下文文本上限；最终完整正文和历史裁剪仍由服务端验证。
3. 点击发送或 `Ctrl + Enter`，查看实际模型目的地、生成用途与当前问题。弹窗说明本次文本及服务端选取的成功对话历史将外发，可能产生费用。每次发送／原请求重放都需重新勾选确认，取消不提交。
4. 可靠受理后显示“已受理／生成中”；成功时展示完整文本回答。普通 Enter 保留换行。再次发送使用最新会话版本及新的幂等键。
5. 刷新或重新选择会话，从耐久历史恢复消息和执行状态；“加载更早的消息”使用排他的提交序号游标，按时间顺序展示。

本阶段为文本、非流式聊天；服务端负责组装多轮上下文，浏览器不重传自己拼装的历史。模型输出按普通文本呈现，保留换行，不作为 HTML
执行。 重新生成、取消、SSE、Markdown／代码块增强、附件、文章资料和旧聊天迁移尚未接入该页面。

## 状态和恢复

- 历史来自 `GET /api/ai-new/conversations/{id}/turns`。准备、待受理、模型受理／运行与终态分别展示，不把 HTTP 202 当作生成成功。
- 有未结束提交时禁止新消息。每 2 秒通过 `GET /api/ai-new/conversations/{id}/turns/{turnId}`
  查询当前活动提交并更新分页缓存，在完成、查询错误、页面离开或观察 5
  分钟后停止；后台页面不持续轮询。暂停后可明确重新查询，页面不会自行判定执行失败。历史与事务优化详见 [第一批说明](../../backend/arte-ai-new/MINIMUM_CHAT_SERVICE.md#第一批性能与事务优化2026-10-03)。
- POST 使用独立 `Idempotency-Key`，不自动重试；确认受理后清理本地待核对请求。失败、取消或超时不伪造回答；`OUTCOME_UNKNOWN`
  明示可能已外发和产生费用。
- 不明提交在 **sessionStorage** 暂存完整原文本、原预期版本和幂等键，按用户／租户／空间／会话隔离。先保存再发送，无法保存则不派发；同一浏览器会话刷新后仍可核对。
- 查询发现相同键已受理／已拒绝时清理本地请求，不重新调用模型。仍在 PREPARING／READY
  或查询未找到时，仅由用户明确“重放原提交”，保持原请求不变，并再次确认外发。历史查询失败时禁止重放。
- 明确且无副作用的边界拒绝按稳定错误处理并刷新版本；不明受理保留原请求。版本冲突不自动改版本重试。待核对请求已由查询确认时，打开着的原重放弹窗也不会创建新请求。
- 退出登录或切换账号清理新模块缓存和待核对文本；切换会话／空间的迟到响应不更新旧界面或缓存。会话存储不是跨浏览器恢复机制，退出后仍未受理的准备记录需要服务端核对，不能换键重发。

## 手工验收

1. 在已配置环境发送一个短问题：确认弹窗实际目的地与用途，取消时没有提交请求；确认后看到受理、生成和完整回答。
2. 连续追问，刷新页面，确认历史及会话版本恢复。检查数据库用户提交与模型执行引用，不在聊天表复制终态结果。
3. 生成中输入区域禁用；成功后可以继续发送，使用新的键。完成后网络面板不再周期查询该历史。
4. 制造提交响应丢失：先查询历史；有原执行时直接展示，没有关联时手动重放。检查文本、预期版本和键保持不变，没有重复执行或重复预留预算。
5. 输入超出字节上限的中文文本，发送按钮禁用；拒绝会话存储时不发送。权限撤销后的历史查询不展示旧消息。
6. 超时／结果未知只展示对应状态，不能当作无费用失败。执行恢复由既有模型链核对，不自动再次派发供应商。

自动验证使用真实 Ant Design 组件、React Query、模拟 HTTP，以及后端 H2 和供应商测试适配器。 本次没有开启实际配置、执行实际数据库脚本或使用真实供应商，生产
MySQL／登录菜单／浏览器视觉和真实模型联调仍需在部署环境验收。
