# AI 对话测试页面

约定式路由 `/AI/Chat`，HTTP 封装统一复用 `src/services/arte-ai`。登录、Token 和语言沿用现有请求拦截器。

## 调试流程

1. 应用配置，填写当前账号有权使用的租户、工作空间、固定 Capability/Binding 版本和预算引用。
2. 创建或选择会话。页面读取最新会话版本、历史轮次及预算；查询成功且可用余额为正时，可以输入消息。
3. 发送纯文本消息。`turnsForChat` 返回 HTTP 202 和 invocationId，只代表已经受理；页面订阅 SSE
   完成通知，通过现有状态和结果接口读取权威数据；连接不可用时每 10 秒恢复查询。
4. 完成后自动刷新会话版本、最新历史页和预算，再发送下一轮。重新选择会话或刷新页面会从后端恢复历史及未完成调用的状态。

会话列表每页 20 条；历史每页 10 轮，默认显示最新页，可查看旧页。每轮由 Turn 的用户消息和 Invocation
的已提交结果组成，展示执行状态、完整／部分回复、Token 用量、错误码、失败阶段和关联 ID。回复按普通文本渲染。

金额保留后端十进制字符串，展示额度、预留、已扣和可用金额。未初始化、查询失败、零或负余额会阻止新消息；正余额不保证足够支付本次调用，最终仍由后端校验和预留。页面可手动刷新预算，不自动初始化或重置账户。

## 多轮上下文

客户端只提交本轮用户文本，不能注入角色或历史。服务端从当前主体所属会话的最近十轮中加载完整、成功、纯文本的回复，形成
USER/ASSISTANT 对及本轮 USER，并记录实际选入的 Turn ID。失败或部分输出不作为后续模型上下文；输入字节或 Token
容量超限明确拒绝，不静默截断。

活动调用期间禁止继续发送。`UNKNOWN` 表示结果尚未确认，可能仍占用会话和预算，页面展示部分结果并阻止继续；需要先由后端核对，再刷新历史。页面不自动重新生成或重发这类调用。

## 重试与切换

每次新消息生成独立幂等键，重复点击只发一次。网络错误、408 或 5xx 后保留原消息、版本、配置和键；“重试提交”复用完全相同的请求。明确的
4xx 拒绝允许修正草稿；409 自动刷新版本与预算，之后由用户重新发送。服务端重放使用原快照历史，避免后续轮次改变原请求语义。

状态查询失败可继续查询原调用；达到配置超时加 30 秒的观察期限会暂停查询，并保留
invocationId。暂停查询不取消后端执行。翻阅旧历史页仍观察已知活动调用。切换会话／工作空间或离开页面会取消旧请求与定时器，忽略迟到响应。

尚不明确的提交重试信息只保存在当前组件中；离开会话或刷新页面后，请先查看历史，确认原消息是否受理，再决定是否发送。未应用的配置修改不会参与请求，并暂时禁止操作。仅修改生成参数不清空当前会话；改变租户或工作空间会清空选择。

## 后端运行条件

已执行表结构与菜单权限后，还需要发布引用、当前账号的授权范围、预算初始化、供应商凭据，以及：

```properties
arte.ai-new.enabled=true
arte.ai-new-generation.enabled=true
arte.ai-new-execution.enabled=true
arte.ai-new-execution.worker-enabled=true
```

聊天提交需要 `ai:invoke`、`ai:conversation` 和 `ai:read` 配置授权；预算查询与执行结果查询使用 `ai:read`
。凭据通过后端配置引用的环境变量（示例为 `ARTE_DEEPSEEK_API_KEY`）提供，不填写到网页或浏览器缓存。

本机 `backend/profile/app.properties` 已启用 Worker。该本地配置不进入 Git；示例配置仍默认手动派发。修改 profile
后请重新构建并重启后端，使资源过滤结果更新；仅重启已有旧构建可能仍读到旧值。Worker 会处理已受理的 Outbox，模型费用受后端预算约束。

## 验证

```sh
cd frontend
npm test -- src/pages/AI/Chat src/services/arte-ai
```

覆盖配置、会话管理、消息受理、SSE 通知及低频恢复、结果／历史关联、多轮版本推进、精确金额、预算失败、幂等重试、409、UNKNOWN、旧页浏览与切换取消。后端
H2 加本机模拟 HTTP/SSE 集成测试验证实际模型请求携带此前 USER/ASSISTANT 历史、十轮上限、容量拒绝，以及后续轮次完成后的原请求重放；不使用真实模型凭据。

## SSE 连接与恢复

`watchInvocation` 使用带 Bearer Token 和当前语言的 POST/fetch；通知只包含调用 ID、sequence 和 kind，不展示未提交的输出。
正常连接期间不设置循环状态查询。提交受理／恢复连接时确认状态，STARTED、TERMINAL 和 BUDGET_CHANGED 通知触发权威查询。回答完成先刷新结果和历史；本次
budgetState=RESERVED 时保留订阅并阻止继续提交，结算后刷新预算并结束观察。 结算不增加 Invocation.version，不重复读取相同版本的结果或重新连接
SSE。页面展示本次预算状态；待对账保留预留，UNKNOWN 仍须由后端核对。

每 10 秒进行断线恢复查询并尝试携带最后处理序号重连。服务端 15 秒心跳；前端 45 秒无数据会关闭旧连接。 401/403
停止自动请求，需恢复登录或权限后继续；410 恢复权威快照后针对该调用使用低频 HTTP，避免重复请求同一过期游标。
切换会话、空间或离开页面会取消连接和恢复定时器。恢复流程不自动重新提交消息。

后端 EVENT 发布器与 DISPATCH Worker 共用现有 worker-enabled 开关，重新构建并重启后端即可注册新增 SSE 接口，无须再次执行建表脚本。
后端已支持 Redis 跨实例通知；`arte.ai-new-events.transport=redis` 复用现有 Redisson，各节点需共享数据库并使用相同 channel。
默认 local
适合单实例。详情见 [后端 SSE 文档](../../../../../backend/arte-ai/INVOCATION_HTTP_API.md#预算变更与-redis-跨实例广播)。
无新增数据库脚本；逐字输出不在本步范围内。
